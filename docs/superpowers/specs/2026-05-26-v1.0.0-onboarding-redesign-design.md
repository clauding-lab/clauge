**Status:** designed, not yet implemented.

## Goal

Two coupled wins for v1.0.0, both required before IAP launch:

1. **Onboarding compresses to 1–2 clicks.** No Keychain dialog in the first-launch flow. No mandatory browser extension. No "remember to click Always Allow" cognitive load.

2. **Architecture becomes Terms-of-Service-clean.** Stop reading Claude Code's OAuth token from `Claude Code-credentials` Keychain entry — that path is explicitly banned by Anthropic's Feb 19, 2026 policy update. Plan-ring data becomes opt-in via user-pasted API key.

The IAP plan (v1.0.0) requires both. Charging money for a product that quietly violates someone else's ToS is its own commercial and legal hazard.

## Locked-in decisions (the five brainstorm answers)

Adnan approved all five on 2026-05-26 BDT.

| # | Topic | Decision |
|---|---|---|
| 1 | Extension's fate | Demote from wizard to Settings tile. Maintain Chrome web-store listing as "alternative for browser-native users." |
| 2 | Migration for existing v0.9.x users | Release notes only. No auto-re-wizard. Existing users keep their setup; new shape applies only to fresh installs. |
| 3 | No-Claude-Code edge case | Soft-skip in wizard + inline help (`"Run \`claude /login\` then click Retry"`) + persistent banner on dashboard if no data sources connected. Don't hard-gate. |

| 5 | ToS path | **Option C — manual API key paste.** Stop reading `Claude Code-credentials` Keychain entry. Add `sk-ant-api03-*` paste UI in Settings for users who want plan-ring data. claude.ai cookie path unchanged. Transcript parsing remains the default data source. |

## Architecture change (v0.9.x → v1.0.0)

| Component | v0.9.x (today) | v1.0.0 (target) |
|---|---|---|
| Code CLI usage data — token spend | Transcript files (`~/.claude/projects/*.jsonl`) | **Unchanged** — transcript files |
| Code CLI usage data — plan ring (5h limits, tier) | OAuth token from `Claude Code-credentials` Keychain → `api.anthropic.com/api/oauth/usage` (**ToS-grey**) | Optional `sk-ant-api03-*` user-pasted key → `api.anthropic.com/v1/organizations/usage_report/messages` (**ToS-clean, sanctioned**) |
| claude.ai consumer usage | Browser extension OR Settings WebView sign-in | Wizard WebView (default) + Settings re-trigger |
| Plan-ring data availability | Always on (via OAuth token) | Opt-in via Settings API key paste |
| Keychain prompt for `Claude Code-credentials` | Yes — re-prompts each launch on unsigned builds | **Never** — entry never read |
| Code signing | None (DMG unsigned; only MAS submission signed) | Apple Developer ID + notarization on every DMG |
| Browser extension role | Default path in wizard step 4 | Optional alternative in Settings |
| Wizard step count | 5 (Welcome / Keychain expect / Other settings / Install Sync / Connect) | 3–4 (Welcome / Sign in to claude.ai / [optional CLI install] / Done) |

## The new wizard shape

```
Step 1: Welcome to Clauge
   "Clauge tracks your Claude usage from the menu bar."
   [ Get started → ]
        │
        ▼
Step 2: Sign in to claude.ai (skippable)
   "Connect to see your Claude Pro / Max plan usage."
   [ Skip for now ]     [ Sign in → ]
        │                    │
        │                    ▼ (embedded WebView at claude.ai/login)
        │                    User signs in → cookie captured
        │                    via existing claude_ai_session.rs
        │                    │
        └────────────────────┤
                             ▼
Step 3: Install `clauge` terminal command (skippable, macOS only)
   "Run `clauge` from any terminal to open the dashboard."
   [ Skip for now ]     [ Install → ]
   (Rolled in from v0.9.5 batch-1 plan — install_cli_symlink IPC
   exists; only the UI was missing. Step is macOS-only; Windows
   gets a "Coming in a future release" variant.)
        │
        ▼
Step 4: Done
   "Clauge is ready. Open the dashboard or wait for it in your
   menu bar."
   [ Open dashboard ]
```

**Total: 2 button clicks for the default path (Get started → Sign in → auto-skip if no Mac CLI desire → Open). 1 OS-level dialog (only if the user opts into the in-wizard claude.ai sign-in, and that's a modal window, not a system prompt). Zero Chrome extension prompts.**

For repeat launches (signed builds, prior auth): zero prompts. Dashboard opens populated.

## Engineering phases

Hour estimates are rough, assuming nothing weird in CI. Re-estimate during writing-plans.

### Phase 1 — Developer ID signing + notarization (4–6h, CI only)

- Generate Developer ID Application cert at developer.apple.com (Team ID `CY4FK9S7X9`)
- Export as `.p12` from Keychain Access with strong password
- Base64-encode the `.p12`, paste into GitHub Actions secret `APPLE_CERTIFICATE`
- Configure 6 more secrets: `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY` (full string `Developer ID Application: <Name> (CY4FK9S7X9)`), `KEYCHAIN_PASSWORD` (random), `APPLE_API_ISSUER`, `APPLE_API_KEY`, `APPLE_API_KEY_PATH`
- Generate App Store Connect API key (`.p8` file) for notarization
- Add ~15-line "Import Apple Developer Certificate" step to `release.yml` before tauri-action invocation
- Pass `APPLE_*` env vars explicitly on the tauri-action step
- Test on a `v1.0.0-rc.1` tag

**Acceptance:** `codesign -dvv` against the v1.0.0-rc.1 DMG shows Team ID `CY4FK9S7X9` + valid Developer ID Application identity. `spctl -a -v` reports "accepted source=Notarized Developer ID".

### Phase 2 — Remove `Claude Code-credentials` Keychain reading (4–6h, Rust + JS cleanup)

- Identify and remove all paths that read the `Claude Code-credentials` Keychain entry. Current callers (from grep): `src-tauri/src/keychain.rs::*`, `src-tauri/src/anthropic_oauth.rs::*`, `wizard_complete` IPC, `refresh_credentials` IPC.
- Delete or deprecate `anthropic_oauth.rs` (the Bearer-token reqwest client)
- Remove `api.anthropic.com/api/oauth/usage` calls entirely
- Update `wizard_complete` to NOT trigger Keychain read (just sets the completed flag)
- Update `connections.js` STATE_LABELS — `claude_code` row becomes informational ("Transcript data from `~/.claude/projects/`"), no auth UI
- Remove "Refresh credentials" button from Settings → Connections (or repurpose for transcript re-scan)

**Acceptance:** `grep -r "Claude Code-credentials\|api/oauth/usage" src-tauri/ lib/ public/` returns nothing (or only test fixtures). App launches without ever triggering the Keychain ACL prompt.

### Phase 3 — API key paste UI in Settings (6–8h, full-stack)

- New IPC commands in `src-tauri/src/ipc.rs`:
  - `set_anthropic_api_key(key: String) -> Result<(), String>` — validates `sk-ant-api03-*` prefix, writes to Keychain under `com.clauding.clauge.anthropic-api-key`
  - `get_anthropic_api_key() -> Option<String>` — reads from Keychain (our own entry, no ACL prompt because same code signature)
  - `clear_anthropic_api_key() -> Result<(), String>` — deletes the entry
  - `test_anthropic_api_key() -> Result<TestResult, String>` — calls a cheap endpoint (e.g., `/v1/messages/count_tokens` with a tiny payload) to verify the key works
- New module `src-tauri/src/anthropic_admin.rs`:
  - `reqwest::Client` with `x-api-key` header injection
  - `fetch_usage_report(api_key, start_date, end_date)` calling `api.anthropic.com/v1/organizations/usage_report/messages`
  - Maps response into Clauge's existing plan-ring shape (or adapts the UI to the new shape — TBD during writing-plans)
- New Settings UI in `public/settings/` (or wherever Settings lives — verify during writing-plans):
  - "Plan-ring data" section with paste field + status indicator + link to `https://console.anthropic.com/settings/keys`
  - Visible state machine: NOT_SET / VALIDATING / VALID / INVALID
  - "Why do I need this?" disclosure: explains that consumer Claude Pro / Max plans don't include API access, and that this is the ToS-sanctioned path
- Update `ClaugeBridge` facade with the 4 new commands

**Acceptance:** Pasting a valid `sk-ant-api03-*` key in Settings, clicking "Test", shows VALID. Dashboard plan-ring updates with API-tier data within 30s. Pasting an invalid key shows INVALID with a friendly message.

### Phase 4 — New wizard (6–8h, JS + HTML)

- Replace `public/onboarding/index.html` with the new 3–4 step structure described above
- Replace or refactor `public/onboarding/onboarding.js`:
  - Drop the keychain-prompt expectation step (was step 2)
  - Drop "Other Settings" step (was step 3 — fold into Settings UI for v1.0.0)
  - Drop "Install Clauge Sync" step (was step 4)
  - Drop "Ready to Connect" step (was step 5)
  - Add new "Sign in to claude.ai" step: button calls `ClaugeBridge.openClaudeAiLogin()`, watches for `connections-updated` event to auto-advance
  - Add "Install CLI" step (rolled in from v0.9.5 batch-1 spec; same content as that spec described)
- Migrate the 5 raw invokes in `onboarding.js` to `ClaugeBridge` (rolled in from v0.9.5 batch-1 spec)
- Update progress bar `<progress max>` to new step count
- Add inline edge-case help text for no-Claude-Code state (per decision #3)

**Acceptance:** Fresh install runs the wizard end-to-end in `cargo tauri dev`. Skip path skips cleanly. Sign-in path opens WebView, completes, advances. Dashboard appears populated with whatever data sources connected.

### Phase 5 — Extension demotion (2–3h, JS + HTML)

- Remove `Install Clauge Sync` wizard step (already covered in Phase 4)
- Add "Browser extension (alternative)" tile to Settings → Connections
- Tile shows install link (`https://chromewebstore.google.com/...`), status indicator (`active` / `not_detected`), and short rationale ("Use this if you prefer browser-native authentication")
- For users who already have the extension active in v0.9.x: existing connections-status panel keeps working; one-time toast on v1.0.0 first launch: "The extension is no longer required. You can also sign in directly from this app."

**Acceptance:** Settings has the tile. Extension still works for existing users. Wizard doesn't reference the extension.

### Phase 6 — Edge case handling (2–3h, full-stack)

- Add "Test connection" button to Settings → Connections that runs all three checks (transcript files presence, API key validity, claude.ai cookie validity)
- Add persistent banner on dashboard: "No Claude data sources connected. Sign in or paste an API key in Settings." Auto-dismisses when any source connects.
- Add inline guidance in wizard sign-in step for "no Claude Code" state: "If you haven't signed into Claude Code yet, open a terminal and run `claude /login`. Transcripts will appear automatically once you start using it."

**Acceptance:** User with NO data sources sees the banner. Test connection button reports per-source status. Inline help appears when wizard detects transcript folder is empty.

### Phase 7 — Runbook documentation (1h)

## Migration story (existing v0.9.x users)

On first launch of v1.0.0:

- App reads its OWN Keychain entries (claude.ai cookie, new API key if migrated) without prompting — these were already granted to Clauge's signature in v0.9.x.
- App stops reading `Claude Code-credentials` entirely — the entry stays in the user's Keychain untouched (Claude Code itself still uses it).
- Banner appears: "We've simplified Clauge auth. Some plan-ring data may be unavailable until you add an API key in Settings."
- Existing claude.ai cookie continues working — no re-sign-in required.
- `onboarding_completed=true` stays true; new wizard doesn't re-trigger for existing users.

**Net effect:** existing users lose plan-ring data (was OAuth-token-sourced) until they paste an API key, but gain ToS-clean architecture + signed-app polish (no more Gatekeeper warnings). No data loss; no settings reset; no re-onboarding required.

## Risks + mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| API key surface is too narrow — most Claude Pro/Max users don't have API access, plan-ring becomes unavailable to most users | High | Clear UX messaging in Settings + clean degradation. Accept as the ToS-clean tradeoff. Mention upfront in release notes. |
| Notarization fails in CI on first attempt | Medium | Phase 7 runbook documents debugging. Use API-key path (more robust than app-specific password). Test on `v1.0.0-rc.1` tag before final v1.0.0. |
| Existing claude.ai cookies expire mid-update | Low | WebView re-trigger from Settings still works. Toast user when 401/403 detected. |
| `release.yml` `set-key-partition-list` step fails silently on the GitHub runner | Medium | Run a `codesign --display --verbose` sanity check immediately after the import step; fail the build if Team ID doesn't match `CY4FK9S7X9`. |
| User pastes a `sk-ant-api03-admin-*` key by mistake | Low | Validation rejects keys that don't match the expected prefix pattern. |
| First signed release still prompts ONCE for the claude.ai cookie Keychain entry (because our own Keychain ACL was tied to prior ad-hoc signature) | High | Document in release notes. After first launch, ACL persists. One-time cost. |

**Rollback:** revert the v1.0.0 release tag. Existing v0.9.4 users on the auto-updater channel get v0.9.4 back via `latest.json`. No data migration to unwind. Worst case: a few hours of "no plan-ring data" for users who upgraded.
