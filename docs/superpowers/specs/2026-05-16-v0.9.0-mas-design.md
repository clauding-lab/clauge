## Problem

The Mac DMG flavor (shipped through GitHub Releases) has three structural limits:

1. **Gatekeeper warning on first install** — macOS shows "this app was downloaded from the internet" because the DMG is ad-hoc signed, not notarized.
2. **No App Store search visibility** — Mac users hunting for menu-bar utilities don't find Clauge through Spotlight, Mac App Store search, or the Apple TV+/iCloud/etc. cross-link surfaces.
3. **Self-managed update infrastructure** — Clauge runs its own gh-pages `latest.json` mirror and minisign-signed binaries. Works fine but requires manual operations on every release.

The architectural blockers for Mac App Store distribution:

- The **macOS App Sandbox** forbids reading another app's data folder (`~/.claude/`, written by Claude Code CLI) without an explicit user grant via the user-selected file entitlement family.
- Apple's **Mac App Store policy** forbids in-app updates — the App Store owns the update channel. The existing Tauri auto-updater plugin must be removed from the MAS-flavor build.
- The MAS build must be signed with a `3rd Party Mac Developer Application` certificate from an active Apple Developer Program account ($99/yr).

The original v0.8.0 MAS spec also proposed requesting a **cross-app keychain entitlement** (`keychain-access-groups` including `com.anthropic.ClaudeCode`) so Clauge could read the Claude Code OAuth blob from the macOS Keychain — but Apple may deny this on the grounds that "your app shouldn't read another team's keychain." v0.8.0's filesystem credential reader (shipped for Windows) makes this entitlement unnecessary; we use the same `.credentials.json` filesystem path on MAS-flavor that Windows already uses, behind the security-scoped bookmark grant.

## Decision

Ship a sandboxed MAS-flavor build alongside the existing DMG and NSIS flavors. Three flavors total, all produced from the same git tag via build matrix.

The MAS flavor:

- Targets the Mac App Store via Apple Developer ID signing (`3rd Party Mac Developer Application` cert)
- Runs inside the App Sandbox with a single user-granted security-scoped bookmark for **`~/.claude/`** (the parent directory containing both `.credentials.json` and `projects/*.jsonl`)
- Uses the **filesystem credential reader** (v0.8.0 Windows path) on Mac MAS — `read_claude_code_credentials_filesystem` reads `~/.claude/.credentials.json` directly inside the security scope. No cross-app keychain entitlement requested.
- Reads JSONL session files from `~/.claude/projects/` inside the same security scope (passed to the SEA sidecar via `CLAUDE_DIR` env at spawn time, with a long-lived `ScopedHandle` held by the supervisor for the sidecar's full lifetime)
- Replaces the Tauri auto-updater with a "Get latest version on the App Store" link that opens `macappstore://apps.apple.com/app/clauge/idXXXXXXXXX`
- Replaces the v0.8.1 "Permissions/Keychain" wizard step at position 2 with a new step labeled "Grant access to your Claude Code logs" — fires NSOpenPanel pre-selected at `~/.claude/`, persists the security-scoped bookmark. **Same 5-step total**; Mac MAS never touches Keychain Services so the old step's copy would mislead.
- Adds a 4th Settings → Connections row showing the bookmark state (granted / not_granted)

The DMG and NSIS flavors stay untouched. **MAS submission is a side workstream gated by Apple's review timeline (1–4 weeks).** v0.9.0 ships when Apple approves the listing.

## Architecture

### Three-flavor build matrix

| Flavor | Distribution | Sandbox | Auto-updater | Tauri config | OS target |
|---|---|---|---|---|---|
| **DMG** | GitHub Releases (minisign-signed) | No (full FS access) | Yes (Tauri plugin) | `tauri.conf.json` | macOS |
| **NSIS** | GitHub Releases (Authenticode optional) | No | Yes (Tauri plugin) | `tauri.conf.json` | Windows |
| **MAS** | Mac App Store | Yes (App Sandbox) | No (Apple owns updates) | `tauri.mas.conf.json` overlay | macOS |

The `mas` Cargo feature flag (`#[cfg(feature = "mas")]`) gates the MAS-only Rust paths (`security_scoped_bookmark.rs`, the filesystem-reader Mac branch, the "Check for Updates" → Store redirect). The DMG and NSIS flavors compile with default features.

### Credential reading — the architectural pivot from the v0.8.0 MAS spec

**Pre-v0.8.0 (original MAS plan):** Mac DMG read credentials from Keychain Services. The MAS plan proposed requesting `keychain-access-groups` containing `com.anthropic.ClaudeCode` so Mac MAS could also read from Keychain. **Apple-review risk: high** (cross-team keychain access is unusual).

**Post-v0.8.0 (Windows port):** v0.8.0 added a filesystem reader for Windows that reads `%USERPROFILE%\.claude\.credentials.json` directly. The blob schema is byte-for-byte identical to the Mac Keychain blob (verified empirically — `docs/superpowers/notes/2026-05-15-windows-claude-code-creds.md`).

**v0.9.0 MAS:** Use the same filesystem reader on Mac MAS. The user grants `~/.claude/` once via NSOpenPanel; Clauge reads `~/.claude/.credentials.json` inside the security scope. **No cross-app keychain entitlement requested.** App Review surface area shrinks dramatically.

```
                    MAC DMG              MAC MAS                WINDOWS NSIS
read credentials   Keychain Services    .credentials.json      .credentials.json
                   (com.anthropic.       inside security        directly
                    ClaudeCode group)    scope                  (no sandbox)
```

The cfg-gating in `keychain.rs`:

```rust
#[cfg(all(target_os = "macos", not(feature = "mas")))]
fn read_claude_code_credentials() -> Result<...> {
    // Keychain Services (existing v0.7.x code, unchanged)
}

#[cfg(all(target_os = "macos", feature = "mas"))]
fn read_claude_code_credentials(app: &AppHandle) -> Result<...> {
    // Filesystem reader inside security scope.
    // Calls into security_scoped_bookmark::with_scoped_path
    // OR receives the path from the long-lived supervisor scope.
}

#[cfg(target_os = "windows")]
fn read_claude_code_credentials() -> Result<...> {
    // Filesystem reader (existing v0.8.0 code, unchanged)
}
```

**Signature compatibility note:** the MAS Mac branch needs the security-scoped path resolved to read `~/.claude/.credentials.json` inside the App Sandbox. The DMG Mac branch and Windows branch don't. Three implementation options:

- **Option A — Global signature change to take `&AppHandle`** (originally proposed; cost was underestimated): forces a ripple through `keychain_cache.rs`. The cache wraps the function in a closure type `type ReaderFn = Box<dyn Fn() -> Result<...> + Send + Sync>` (line 24 on `main`); adding an arg breaks the closure type, every cache caller (`get_or_load`, `refresh`, the OAuth-401 clear path) needs an `AppHandle` in scope, and the test-injection mock signature changes. Not just "3 unused-arg lines."
- **Option B — Path resolution via process-wide `OnceLock<PathBuf>`** (**recommended**): the supervisor (`sidecar::spawn_and_supervise`) already calls `acquire_scoped_path(&app)` before spawning the sidecar and holds the `ScopedHandle` for the loop's lifetime. Have the supervisor also populate a `static MAS_CLAUDE_DIR: OnceLock<PathBuf>` immediately after acquisition. The zero-arg `fn read_claude_code_credentials() -> Result<...>` MAS-Mac branch reads from `MAS_CLAUDE_DIR.get()` and joins `.credentials.json`. Keeps the existing `ReaderFn` closure type intact — no cache rewrite, no AppHandle plumbing, no test signature churn.
- **Option C — Separate `read_claude_code_credentials_mas` function dispatched at call site**: viable but the cache wrapper still needs two pathways (or dispatch logic inside the cache closure), and the test-injection surface doubles.

Recommend Option B. Implementation detail; see plan.

### Security-scoped bookmark for `~/.claude/` (parent dir)

The grant target moves from `~/.claude/projects/` (original spec) to **`~/.claude/`** (parent of both `.credentials.json` and `projects/`). One bookmark, both files accessible.

**First-launch flow (MAS only):**
1. Wizard step 2 fires. Copy:
   > **Grant access to your Claude Code logs**
   > Clauge needs read-only access to `~/.claude/` to read your Claude Code login and per-session analytics. macOS will show a folder picker — click **Choose** on the pre-selected folder. You only do this once.
   >
   > **Heads up:** if you haven't logged in to Claude Code yet, open a terminal and run `claude /login` first. Clauge can't read what isn't there.
   >
   > [Grant Access] [Skip for now]
2. Grant → invokes `grant_claude_dir_access` IPC. Tauri's dialog plugin opens NSOpenPanel pre-selected at `$HOME/.claude/`. User clicks Choose.
3. App receives NSURL → converts to bookmark blob via `NSURL.bookmarkDataWithOptions(.withSecurityScope)` → persists to Tauri store under key `claude_dir_bookmark`.
4. Wizard advances to step 3 (Connect explanation).

**Per-launch use (MAS only):**
1. At `spawn_and_supervise` start, call `acquire_scoped_path(&app)` → returns `(String, ScopedHandle)`.
2. `ScopedHandle` lives in `_mas_scope_guard` local for the supervisor's lifetime.
3. The resolved path is set on `CLAUDE_DIR` env for the spawned sidecar — sidecar reads `$CLAUDE_DIR/projects/*.jsonl` via inherited security scope.
4. The same path is used by `read_claude_code_credentials` (filesystem reader Mac MAS branch) to read `$CLAUDE_DIR/.credentials.json`.

**Skip flow:**
- Skip stores `localStorage['clauge.claude_dir_grant_dismissed_at']` so the dashboard's 4th Connections row shows "Not granted — click to grant" instead of being hidden.
- Sidecar starts with `CLAUDE_DIR=$HOME/.claude` (default fallback). Inside the App Sandbox, `$HOME` is **rewritten** to `~/Library/Containers/com.clauding.clauge/Data`, so this path resolves to a container subfolder that doesn't exist — no JSONL or credentials available. Dashboard shows empty state with a CTA to grant. (Sandbox HOME redirection is the mechanism, not access denial — same end-user behavior either way.)

**MAS sandbox entitlements (entitlements.mas.plist):**

```xml
<key>com.apple.security.app-sandbox</key>
<true/>
<key>com.apple.security.files.user-selected.read-only</key>
<true/>
<key>com.apple.security.files.bookmarks.app-scope</key>
<true/>
<key>com.apple.security.network.client</key>
<true/>
<key>com.apple.security.network.server</key>
<true/>
<key>com.apple.security.cs.allow-jit</key>
<true/>
```

**No `keychain-access-groups`.** That's the architectural win over the v0.8.0 MAS spec.

### Drop Tauri auto-updater for MAS flavor

App Store policy requires Apple to own updates. The MAS-flavor build:

- `tauri.mas.conf.json::plugins.updater: null` removes the updater config (verified RFC 7396 merge behavior at v0.8.0 ship time).
- The Rust-side updater plugin registration in `lib.rs` (grep for `tauri_plugin_updater::Builder::new().build()`; currently ~line 37 on `main`) should ALSO be cfg-gated to `#[cfg(not(feature = "mas"))]` — JSON null only removes config, not the plugin init. This was a Task-5 caveat in the original v0.8.0 MAS plan; deferred to Task 9 there. **For v0.9.0, do it in the Foundation phase** so MAS builds are clean from the start.
- The launch-time auto-update spawn in `lib.rs` (the `tauri::async_runtime::spawn` block calling `ipc::check_for_updates` on cold start — currently ~lines 224-229 on `main`) is `#[cfg(not(feature = "mas"))]` — already-correct fix from the local commit `3edb8fe` which carries forward.
- The `check_for_updates` IPC body is cfg-gated:
  ```rust
  #[cfg(feature = "mas")] {
      app.shell().open("macappstore://apps.apple.com/app/clauge/idXXXXXXXXX", None)?;
      return Ok(UpdateStatus::OpenedStorefront);
  }
  #[cfg(not(feature = "mas"))] { /* existing v0.7.3 tauri-plugin-updater flow */ }
  ```

### Settings → Connections — 4th row "Claude Code logs"

Inherits the 3-row panel from v0.7.0 + v0.8.1's claude.ai dealarming. Adds a 4th row visible only when MAS flavor's backend includes the `claude_code_logs` field in the `ConnectionStatus` payload:

```
│  Claude Code logs   ●  Granted (~/.claude/)               │
│  Read-only access for credentials + per-session analytics │
│  [Re-select folder]                                       │
```

States:
- **granted** — bookmark blob present in the Tauri store. The connections poll renders this cheaply via `has_bookmark(app)` (one store read; no Foundation FFI). Resolution success is evaluated **once at launch** inside `acquire_scoped_path`. If resolution silently fails later (file moved, permissions changed), reads return empty data and the user re-grants from observation — same recovery as a true stale-state row, simpler implementation.
- **not_granted** — no bookmark blob in the Tauri store (first launch + Skip path, or `clear_bookmark` was called)

The original v0.8.0 spec proposed a tri-state (granted / stale / not_granted). v0.9.0 keeps the simpler 2-state: stale grants surface as "no JSONL data in dashboard" + user clicks Grant access to overwrite. Resolving the bookmark every detect-poll just to surface a 3rd state is expensive Foundation FFI; skipped.

### CI matrix — third row, not separate job

Current `release.yml` on `main` is matrix-shaped (macos-14 + windows-2022 rows from v0.8.0). MAS adds a **third matrix row**:

```yaml
matrix:
  include:
    - { runner: macos-14,     target: universal-apple-darwin, bundles: 'app,dmg', config: '',                     features: '' }       # DMG
    - { runner: windows-2022, target: x86_64-pc-windows-msvc, bundles: 'nsis',    config: '',                     features: '' }       # NSIS
    - { runner: macos-14,     target: universal-apple-darwin, bundles: 'app',     config: 'tauri.mas.conf.json',  features: 'mas' }    # MAS
```

The MAS row uses `--no-sign` (CLI flag, verified at v0.8.0 ship time) so the unsigned MAS .app builds in CI as a transparency artifact. Real signing happens manually via Transporter on a developer's Mac during Task 14.

`continue-on-error: true` on the MAS matrix entry — if it fails, the DMG and NSIS releases still ship. This was the right call in the original spec; preserved.

### MAS submission specifics

Apple Developer Program: $99/yr (calendar-critical prerequisite per memory `project_apple_developer_enrollment_v080`).

App Store Connect listing needs:
- Screenshots (1280×800, 1440×900, 2560×1600 retina) — captured from the actual MAS-built .app running on a real Mac
- App description, support URL (GitHub Issues), privacy policy URL
- App Privacy nutrition label: **Data Not Linked to You: None** (Clauge collects no telemetry); **Data Linked to You: None**
- App Review Information reviewer notes — substantially shorter than v0.8.0 MAS spec required:
  > Clauge analyzes the user's own Claude Code CLI usage. It reads `~/.claude/.credentials.json` (an OAuth token Claude Code wrote during `claude /login`) to call Anthropic's official `api.anthropic.com/api/oauth/usage` endpoint, and reads JSONL files in `~/.claude/projects/` (session history Claude Code wrote during normal use) for analytics. Both are inside the user-granted security-scoped bookmark for `~/.claude/`. No data leaves the user's Mac.

Review timeline: typical 24–72h, longer for first submission. **v0.9.0 ships when approved.**

## Decisions made

| # | Decision | Reason |
|---|---|---|
| 1 | Three-flavor build (DMG + NSIS + MAS) | DMG keeps minisign auto-updater + GitHub Releases. NSIS keeps the v0.8.0 Windows flow. MAS adds App Store discoverability. Three matrix rows, one git tag. |
| 2 | **Filesystem credential reader for Mac MAS** (no cross-app keychain entitlement) | v0.8.0 shipped the filesystem reader for Windows; same code path on Mac MAS dodges Apple's `keychain-access-groups` review risk entirely. Architectural simplification. |
| 3 | **Bookmark target is `~/.claude/` (parent), not `~/.claude/projects/`** | Covers both `.credentials.json` and `projects/`. Single user grant. Cleaner than two separate bookmarks. |
| 4 | Drop the wizard's Keychain step on MAS-flavor; add a Grant-folder step at position 2 | Mac MAS never touches Keychain Services — keeping the explanatory step would mislead users. Same 5-step count, different content. |
| 5 | 2-state Connections row (granted / not_granted) instead of tri-state | Stale detection requires expensive Foundation FFI every detect-poll. The fallback for stale grants is "dashboard shows empty data; user re-grants" — same user experience as tri-state, simpler implementation. |
| 6 | MAS uses CI matrix third row, not separate job | Original v0.8.0 plan had to use a separate job because matrix didn't exist yet. v0.8.0 built the matrix. Third row is now the idiomatic shape. |
| 7 | `is_mas_flavor` IPC for runtime flavor detection | Avoids build-time HTML templating. JS-side `await invoke('is_mas_flavor')` at wizard init + dashboard init is clean and matches the v0.8.1 platform-detection pattern (`body.is-windows`). |
| 8 | Cfg-gate the updater plugin init in `lib.rs` (the `tauri_plugin_updater::Builder::new().build()` line), not just the JSON config | JSON null removes config but doesn't prevent the plugin from registering at runtime. The plugin would fail-silently on launch in MAS (no endpoints) — register-or-skip cleanly via cfg. |
| 9 | Keep the local commits from the prior MAS execution attempt as reference, but rewrite from scratch on `main` | The 13 commits at `bf99499` and earlier predate v0.8.0/v0.8.1/v0.8.2. Architecture has shifted. Rebase would conflict with every file changed. Cleaner to start fresh; salvage specific code (e.g., `security_scoped_bookmark.rs` shape, `ScopedHandle` design) by re-reading the old commits. |
| 10 | MAS submission as calendar-driven side workstream (unchanged from v0.8.0 spec) | Apple review (1–4 weeks) doesn't gate engineering. v0.9.0 engineering can ship to `main` before Apple approves; the MAS listing goes live separately. |
| 11 | **Bundle ID = `com.clauding.clauge`** (same as DMG) | Industry norm (1Password, Bear, OmniFocus pattern). Atomic install replacement — one menu bar icon at a time, less user confusion. State divergence between sandboxed and unsandboxed app data folders is unavoidable regardless of bundle-ID choice. User who wants to preserve DMG-flavor data can back up `~/Library/Application Support/com.clauding.clauge/` before installing the MAS version. |

## Open questions / known unknowns (⚠ verify gates)

- **⚠ Apple's review verdict on the `~/.claude/` security-scoped bookmark request** — unknown until submission. The pattern (user-initiated NSOpenPanel folder grant for reading another app's data folder) is well-precedented (file managers, dev tools, backup apps all do it). Low risk; no need for a fallback design.
- **⚠ `kill_pid_on_port_unix` shell-out works inside the App Sandbox** — same verify gate flagged in the original v0.8.0 MAS spec. `tokio::process::Command::new("lsof")` and `Command::new("kill")` spawn `/usr/bin/lsof` and `/bin/kill` — outside the app bundle. Apple's App Sandbox sometimes blocks system-binary spawns without a `temporary-exception.spawn` entitlement. Phase 5 smoke (Task 11) MUST verify. Fallback if blocked: replace shell-out with `libc::kill(pid, SIGKILL)` syscall (always permitted) and `proc_listpids` for PID lookup via the `libproc` crate. ~half a task's worth of work; not blocking the cycle.
- **⚠ Security-scoped resource lifetime through the spawned sidecar process** — Apple docs imply process-tree scope inheritance: when the parent process holds an active security scope and spawns a child, the child inherits filesystem access. Empirical verification needed in Phase 5. If the child does NOT inherit, fallback is to pass the bookmark blob to the sidecar and resolve in-process — much more work; preferable to avoid. Should "just work" per Apple's documented behavior.
- **⚠ `objc2-foundation` 0.3.x NSURL bookmark API surface** — original v0.8.0 MAS plan's literal Rust code didn't quite match objc2-foundation 0.3.2 bindings. The prior local implementation at `1309d1a` + `400e700` resolved this empirically (used `Result<>` returns instead of out-error params, typed bitflags instead of raw consts, etc.). When implementing v0.9.0, **read the prior local commits as reference** even though they won't apply cleanly.
- **`disabled_reason` enum values from claude.ai** — v0.8.2 mapping handles `org_level_disabled_until` + generic fallback. Not directly MAS-related, but if Apple Review asks why we read claude.ai's `disabled_reason`, the answer is "to surface why a feature isn't available, replacing misleading 'not configured' text" (v0.8.2 spec).

- **✅ RESOLVED 2026-05-16: bundle ID = `com.clauding.clauge` (same as DMG).** See Decisions Made § 11. Confirmed by user during spec review pass; MAS install atomically replaces DMG install (one icon at a time). State divergence between sandboxed `~/Library/Containers/com.clauding.clauge/Data/` and unsandboxed `~/Library/Application Support/com.clauding.clauge/` is unavoidable regardless of bundle-ID choice — accepted. v0.9.0 release notes will include the "MAS install will replace your existing DMG-installed Clauge" note. **No code-level blocker** — `tauri.mas.conf.json` doesn't need an `identifier` override since inheritance from `tauri.conf.json` already supplies the correct value.
