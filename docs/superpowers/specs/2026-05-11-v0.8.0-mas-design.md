# Design: Mac App Store Flavor (Clauge v0.8.0)

**Date:** 2026-05-11
**Author:** brainstorming session (continuation of 2026-05-09 v0.7.0 design; split off 2026-05-11)
**Status:** approved, ready for implementation
**Target version:** v0.8.0
**Scope:** macOS — sandboxed MAS-flavor build alongside the existing DMG flavor from v0.7.0. Adds Apple-review-dependent surfaces (security-scoped bookmark, sandbox entitlements, cross-app keychain access group, App Store submission). Builds on the auth architecture already shipping in v0.7.0.
**Sequencing:** Parallel side workstream to v0.6.0 (Windows port). MAS-flavor build infrastructure + Apple submission begin once v0.7.0 has shipped on the DMG side and the Architecture B/A modules are validated in real use.

**Supersedes:** the MAS-related portions of `docs/superpowers/specs/2026-05-09-v0.7.0-hybrid-mas-design.md` (combined DMG+MAS spec). Per the 2026-05-11 re-sequencing decision (saved in project memory `project_release_sequencing.md`), MAS work is split into a separate v0.8.0 cycle to remove Apple-review risk from v0.7.0's critical path.

**Depends on:** v0.7.0 (`docs/superpowers/specs/2026-05-11-v0.7.0-dmg-design.md`) shipped first. v0.8.0 inherits keychain.rs, anthropic_oauth.rs, claude_ai_session.rs, connections.rs, and the 3-row Connections panel from v0.7.0; v0.8.0 adds a 4th row and the MAS-specific build infrastructure.

**Predecessor:** v0.7.2 (UX + carryover-debt — spec `docs/superpowers/specs/2026-05-14-v0.7.2-design.md`) shipped before this. v0.7.2 implemented the v0.7.x deferred items (Expired state surface, retry-loop ceiling, shared `reqwest::Client`, errno-based keychain errors, magic-number constants) and the first-launch onboarding wizard. v0.8.0's scope is reduced to MAS-flavor build + Apple Developer ID signing + Architecture A data plumbing.

## Problem

v0.7.0 ships the new auth architecture (Architecture B + A) on the DMG flavor only. The DMG flavor:
- Requires a Gatekeeper warning on first install (notarized but not Apple-distributed)
- Doesn't appear in App Store search results — the place macOS users naturally look for menu-bar utilities
- Distributes via GitHub Releases (free, but lower discovery)

The remaining structural limitation: **Mac App Store distribution is blocked at the architectural level on the DMG codepath.** The macOS App Sandbox forbids reading `~/.claude/projects/` (data written by another app — Claude Code CLI) without an explicit user grant via the standard "user-selected file" entitlement family, and the Tauri auto-updater is incompatible with App Store policy.

The architectures needed to unblock MAS distribution are:
- **Security-scoped bookmark for JSONL access:** user picks the `~/.claude/projects/` folder once via NSOpenPanel, the app persists a security-scoped bookmark, and reads via that bookmark on every subsequent launch.
- **Sandbox-compatible build flavor:** separate Tauri config, separate entitlements file, no auto-updater plugin, Cargo feature flag to gate the MAS-only modules.
- **Cross-app keychain entitlement:** request access to the `com.anthropic.ClaudeCode` keychain group so Architecture B works inside the sandbox. Apple-review-dependent.

## Decision

Add a sandboxed MAS-flavor build alongside the v0.7.0 DMG flavor. Both flavors share the same codebase and the same auth architectures (B + A + extension). The MAS flavor adds:

- A security-scoped-bookmark flow for `~/.claude/projects/` JSONL access (the only sandbox-clean way to read another app's data folder)
- A sandbox entitlements file (`entitlements.mas.plist`) requesting App Sandbox, user-selected file read, bookmarks app-scope, and the `com.anthropic.ClaudeCode` cross-app keychain group
- A separate Tauri config overlay (`tauri.mas.conf.json`) that removes the auto-updater plugin and switches to `entitlements.mas.plist`
- A Cargo `mas` feature flag that cfg-gates the MAS-only modules
- A "Check for Updates" → MAS Store redirect (since Apple owns updates inside the Store)
- A first-launch grant-access banner asking the user to grant `~/.claude/projects/` access
- A 4th Settings → Connections row showing the bookmark state

The DMG flavor stays untouched. Both produced from the same git tag. **MAS submission is a side workstream gated by Apple's review timeline (1-4 weeks).** v0.8.0 ships when Apple approves the listing.

## Scope

**Adds (Rust / Tauri):**
- `src-tauri/src/security_scoped_bookmark.rs` (new, cfg-gated to `feature = "mas"`): wraps macOS NSURL security-scoped bookmark APIs via `objc2-foundation`; persists serialized bookmark blob in Tauri store under `claude_projects_bookmark`; `start_accessing_security_scoped_resource()` / `stop_accessing_…` lifecycle.
- `src-tauri/Cargo.toml`: `mas` feature flag (cfg-gates the security-scoped-bookmark module + "Check for Updates" → Store-redirect behavior). Adds `objc2-foundation` to the feature's dependency set.

- `src-tauri/tauri.mas.conf.json` (new): MAS-overlay tauri config; `bundle.targets ["app"]`; references `entitlements.mas.plist`; removes `tauri-plugin-updater` from plugin block.
- `src-tauri/entitlements.mas.plist` (new): App Sandbox + cross-app keychain access groups + user-selected file read + bookmarks app-scope + V8 JIT + network client/server.
- `package.json`: new `build:mas` script wrapping `cargo tauri build --features mas --config ../tauri.mas.conf.json`.
- New CI matrix entry for MAS-flavor build (third row alongside DMG-macOS and NSIS-Windows).
- `docs/RELEASE_CHECKLIST.md` updates for MAS submission flow.

**Adds (frontend):**

**Adds (Apple submission infrastructure):**

**Unchanged (inherited from v0.7.0/v0.7.2):**

- Windows / Microsoft Store path — v0.8.0+ (Windows MSIX is a separate cycle)
- Linux — out of scope as before

- Universal-binary verification of the SEA sidecar inside the sandbox — Phase 1 of plan verifies this empirically before locking the build
- Refresh-token flow for Apple-denial scenarios — if Apple denies the cross-app keychain entitlement, the MAS flavor falls back to Architecture A only (graceful degradation; documented at submission time)

## Architecture

### Two-flavor build

| Flavor | Distribution | Sandbox | Auto-updater | Tauri config | Source of v0.7.x |
|---|---|---|---|---|---|
| **DMG** | GitHub Releases (minisign-signed) | No (full FS access) | Yes (existing flow) | `tauri.conf.json` | v0.7.0 |
| **MAS** | Mac App Store | Yes (App Sandbox) | No (Apple owns updates) | `tauri.mas.conf.json` (overlay) | v0.8.0 |

The `mas` Cargo feature flag (`#[cfg(feature = "mas")]`) gates the MAS-only code paths (security-scoped bookmark module, "Check for Updates" → Store redirect, 4th Connections row). The DMG flavor compiles with default features.

### Security-scoped bookmark for JSONL access (MAS flavor only)

**File:** `src-tauri/src/security_scoped_bookmark.rs` (cfg-gated to `feature = "mas"`)

**First-launch flow:**
1. After dashboard's first render in MAS flavor, banner appears at top:
   ```
   ⓘ Grant access to your Claude Code logs
   Clauge needs read-only access to ~/.claude/projects/ to show
   per-session analytics. One-click setup.
   [Grant Access]                                  [Skip]
   ```
2. **Grant Access** click → Tauri shell opens NSOpenPanel via macOS native API (or via Tauri's dialog plugin if it supports security-scoped variants):
   - Title: "Choose your Claude Code logs folder"
   - Initial directory: `~/.claude/projects/`
   - Buttons: "Choose" (single-folder selection)
3. User clicks "Choose" — macOS records user-initiated selection. App receives an `NSURL` representing the folder.
4. Convert `NSURL` to security-scoped bookmark blob via `NSURL.bookmarkDataWithOptions(.withSecurityScope)`.
5. Persist serialized bookmark to Tauri store as `claude_projects_bookmark` (binary blob, ~1-2 KB).

**Per-launch use:**
1. Read bookmark blob from Tauri store.
2. `NSURL.URLByResolvingBookmarkData(bookmarkData, options: .withSecurityScope)` → `NSURL`.
3. `url.startAccessingSecurityScopedResource()` returns `bool` — `false` means bookmark is stale (folder moved/deleted, or sandbox context rotated).
   - If false: clear stored bookmark; re-show the banner; user re-grants.
4. Read JSONL files via `lib/session-store.js` (exact same logic as DMG flavor; the URL scoping is transparent).
5. `url.stopAccessingSecurityScopedResource()` after read completes.

**Skip flow:** If user clicks Skip in the banner, JSONL reads are no-ops; dashboard shows plan rings only (Architecture B + A continue working). Banner persists in Settings → Connections so user can grant later.

**MAS sandbox entitlements:**
```xml
<key>com.apple.security.app-sandbox</key>
<true/>
<key>com.apple.security.files.user-selected.read-only</key>
<true/>
<key>com.apple.security.files.bookmarks.app-scope</key>
<true/>
```

**⚠ Empirical verification gap (Phase 2 of plan):**
1. `objc2-foundation` NSURL signatures for `bookmarkDataWithOptions` and `URLByResolvingBookmarkData` — the safe Rust wrappers may not match Foundation's option-set encoding exactly. Phase 2 Task verifies on a real Mac before locking the security_scoped_bookmark module.
2. Security-scoped resource lifetime around the SEA sidecar process — the sidecar needs filesystem access for its lifetime; `start_accessing_security_scoped_resource()` is scoped to the calling process. The Rust main process holds the scope and the sidecar inherits via parent-process file descriptors (Unix-standard), but this needs verification in the sandbox context.

### Cross-app keychain access for Architecture B (MAS flavor only)

**MAS sandbox entitlement:**
```xml
<key>keychain-access-groups</key>
<array>
  <string>$(AppIdentifierPrefix)com.clauding.clauge</string>
  <string>$(AppIdentifierPrefix)com.anthropic.ClaudeCode</string>
</array>
```

The second array entry requests *cross-app keychain sharing* — letting Clauge read items written by Claude Code's app team. **Apple's MAS reviewer must approve this.**

**Risk:** Apple may deny on the basis that "your app shouldn't read another team's keychain."

**Mitigation:** documented use case in the App Store reviewer notes:
> "Clauge analyzes the user's own Claude usage data. The keychain entry contains an OAuth token Claude Code already wrote; we read it to call Anthropic's official `api.anthropic.com/api/oauth/usage` endpoint. The user explicitly grants this access via the macOS Keychain prompt at first read."

**Failure mode if Apple denies:** the `read_claude_code_credentials()` call returns `KeychainError::AccessDenied`; Clauge in MAS falls through to Architecture A. DMG flavor (v0.7.0) is unaffected. The MAS submission still ships, just without Architecture B; the connections panel surfaces this state clearly.

### Drop Tauri auto-updater for MAS flavor

App Store policy requires the Store to own updates. The MAS-flavor build:
- Removes `tauri-plugin-updater` from the plugin block in `tauri.mas.conf.json`
- The "Check for Updates" menu item is cfg-gated:
  ```rust
  #[cfg(feature = "mas")]
  fn check_for_updates_button_action() {
      // Open MAS listing instead of in-app updater check
      let _ = open::that("macappstore://apps.apple.com/app/clauge/idXXXXXXXXX");
  }

  #[cfg(not(feature = "mas"))]
  fn check_for_updates_button_action() {
      // Existing tauri-plugin-updater check (DMG flavor)
      crate::ipc::check_for_updates(...);
  }
  ```

### Settings → Connections UI (4th row, MAS-flavor only)

Inherits the 3-row panel from v0.7.0. Adds a 4th row visible only when `feature = "mas"`:

```
│  Claude Code logs   🟢 Granted (~/.claude/projects/)      │
│  Read-only access for per-session analytics                │
│  [Re-select folder]                                        │
```

States:
- 🟢 **Granted** — bookmark resolved successfully on launch, JSONL reads working
- 🟡 **Stale** — bookmark exists but `startAccessingSecurityScopedResource()` returned false (folder moved or sandbox rotated); user must re-grant
- 🔴 **Not granted** — first launch or user dismissed the banner; shows "Grant access" CTA

### Build flavors + CI

**File layout (final after v0.8.0):**
```
src-tauri/
├── tauri.conf.json          # DMG flavor base (from v0.7.0, unchanged in v0.8.0)
├── tauri.mas.conf.json      # MAS overlay (new in v0.8.0): inherits base,
│                            # removes updater plugin, bundle.targets=["app"],
│                            # adds entitlements.mas.plist
├── entitlements.dmg.plist   # From v0.7.0: non-sandboxed, full FS
├── entitlements.mas.plist   # NEW in v0.8.0: sandboxed + keychain groups + bookmarks
└── Cargo.toml               # Adds `mas` feature flag in v0.8.0
```

**Cargo feature flag (added in v0.8.0):**
```toml
[features]
default = []
mas = ["security-scoped-bookmark"]  # cfg-gates MAS-only modules
```

**CI matrix gains a third row (in v0.8.0):**
```yaml
matrix:
  include:
    - { runner: macos-14,     target: universal-apple-darwin, bundles: 'app,dmg', config: 'tauri.conf.json',     features: '' }       # DMG (v0.7.0)
    - { runner: windows-2022, target: x86_64-pc-windows-msvc, bundles: 'nsis',    config: 'tauri.conf.json',     features: '' }       # Windows (v0.6.0)
    - { runner: macos-14,     target: universal-apple-darwin, bundles: 'app',     config: 'tauri.mas.conf.json', features: 'mas' }    # MAS (v0.8.0)
```

The MAS flavor build outputs a sandboxed `.app`. Submission to App Store Connect uses Transporter (or `xcrun altool --upload-app`); this is a manual step (Apple credentials + ASC API key required), documented in `RELEASE_CHECKLIST.md`.

### MAS submission specifics

Apple Developer Program: $99/yr (already needed for any code signing; cost wasn't introduced by v0.8.0). App Store Connect listing needs:
- Screenshots (1280×800, 1440×900, 2560×1600 for Mac)
- App description, support URL, privacy policy URL
- App Privacy nutrition label

**App Privacy declarations (Clauge collects):**
- **Data Not Linked to You:** Anonymous usage analytics — None (Clauge has no telemetry by design)
- **Data Linked to You:** None
- Privacy policy at https://clauding-lab.github.io/clauge/privacy or similar

**App Review Information section** needs reviewer notes explaining:
- Why we request `keychain-access-groups` for `com.anthropic.ClaudeCode`: "Clauge analyzes the user's own Claude Code usage. The keychain entry contains an OAuth token Claude Code already wrote; we read it to call Anthropic's official `api.anthropic.com/api/oauth/usage` endpoint. The user explicitly grants this access via the macOS Keychain prompt at first read."
- Why we use security-scoped bookmark for `~/.claude/projects/`: "Same reason — analyzing the user's own logs. The user picks the folder via NSOpenPanel; we never access it without explicit consent."

**Review timeline:** typical 24-72h, longer for first submission. v0.8.0 ships when approved.

## Decisions made (v0.8.0-specific, building on v0.7.0)

| # | Decision | Reason |
|---|---|---|
| 1 | Two-flavor build (DMG from v0.7.0 + MAS new) | DMG keeps Tauri auto-updater (better UX for direct-download users). MAS gets store discovery + Apple-managed updates. Both produced from one tag. |
| 2 | Security-scoped bookmark for JSONL in MAS flavor | The only sandbox-clean way to read another app's data folder. User-initiated; reviewable; revocable. Skip flow leaves users with plan rings only — graceful. |
| 3 | Drop Tauri auto-updater for MAS flavor | App Store policy requires the Store to own updates. "Check for Updates" button in MAS flavor opens the MAS listing instead. Established pattern (Hayek's app, others). |
| 4 | Cross-app keychain access entitlement requested in Apple review | Required for Architecture B to work in MAS. If Apple denies → graceful degradation to Architecture A (B path silently fails on MAS only). DMG flavor (v0.7.0) unaffected. |
| 5 | Cargo `mas` feature flag, NOT a separate codebase fork | Single source of truth; cfg-gates the MAS-only modules. Cleaner than maintaining two divergent repos. |
| 6 | 4th Connections row "Claude Code logs" added in v0.8.0 (MAS-only) | The first 3 rows ship in v0.7.0 because they apply to both flavors. The bookmark-state row is MAS-flavor-only. |
| 7 | MAS submission as a calendar-driven side workstream | Apple review timeline (1-4 weeks) doesn't gate engineering. v0.8.0 ships when approved; if denied, the implementation work isn't wasted — DMG flavor continues. |

## Open questions / known unknowns (⚠ verify gates)

- **⚠ Apple's review verdict on cross-app keychain entitlement** — unknown until submission. Clauge isn't the first app to request similar (`Usage for Claude` is in MAS already), so precedent suggests approval is plausible. If denied, A fallback is fine.
- **⚠ `objc2-foundation` NSURL signatures for `bookmarkDataWithOptions` and `URLByResolvingBookmarkData`** — verified on a real Mac before locking the security_scoped_bookmark module.
- **⚠ Security-scoped resource lifetime around the SEA sidecar process** — Phase 2 of plan flags this. The sidecar needs filesystem access for its lifetime; the bookmark's start/stop calls need to be paired correctly. Implementation may need a long-lived security-scope task.
- **⚠ Universal vs Apple-Silicon-only for MAS submission** — current DMG is universal (lipo-merged). MAS submission can be the same. Verify during Phase 2 that the SEA sidecar's `clauge-server-universal-apple-darwin` works inside the sandboxed app.
- **MSIX / Microsoft Store path on Windows** — out of scope for this release. The architecture mostly transfers (Windows Credential Manager replaces Keychain; WebView2 replaces WKWebView; AppContainer replaces App Sandbox). Windows hybrid lands in a later cycle (v0.9.0 or whichever Windows-port slot is open at that time).
