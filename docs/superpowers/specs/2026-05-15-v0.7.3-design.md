# Design: Auto-update orphan-sidecar fix + Restart Now UX (Clauge v0.7.3)

**Date:** 2026-05-15
**Author:** brainstorming session (post-v0.7.2 ship + smoke discovery)
**Status:** approved, ready for implementation
**Target version:** v0.7.3
**Scope:** macOS DMG flavor only — same distribution channel as v0.7.0 / v0.7.1 / v0.7.2. No Apple Developer enrollment, no Mac App Store work, no Windows work. Pure hotfix release.
**Sequencing:** v0.7.2 (shipped 2026-05-15) → **v0.7.3 (this spec)** → v0.8.0 (MAS flavor + Architecture A data plumbing)

## Problem

v0.7.2 shipped successfully but post-ship smoke uncovered three bugs in the auto-update flow that, together, caused a confusing UX where users running the auto-update appeared to update on disk but kept seeing the old version in the dashboard:

**Problem 1 — Orphan sidecar process across auto-updates (HIGH).** When the Tauri auto-updater downloads a new version, it replaces `/Applications/Clauge.app` on disk. The user is told to "restart to apply". When they restart the Tauri shell, the `RunEvent::ExitRequested` hook in `lib.rs` IS supposed to kill all sidecar children registered with `AppState::children`. Despite this, in practice (verified post-v0.7.2 ship), an orphan `clauge-server` process from the previous version stayed alive on port 3456 after the user's "restart". The new Tauri shell ran `port_discovery`, found the orphan responding on 3456, took the `External` path, and used the orphan as its sidecar — which served the OLD `package.json` (embedded at SEA-build time) via `/api/health`. The dashboard's Settings panel reads version from `/api/health`, so it kept showing the OLD version even though the on-disk binary was correctly updated. The user only recovered by manually `pkill -f clauge-server` and relaunching.

**Problem 2 — No in-app "Restart Now" affordance after install (MEDIUM).** The current update flow downloads + installs, fires a single macOS notification ("Updated to vX. Restart the app to apply."), and does nothing further. The dashboard shows a passive label "vX available — restart app to apply". There is no button to actually trigger the restart. The macOS notification is easily missed (especially with notification permissions denied or Do Not Disturb on). Users have no clear next-action affordance, and "restart" itself is ambiguous (close-window vs Cmd+Q vs force-quit).

**Problem 3 — v0.7.2 plan Task 17 missed `bash scripts/build-sidecar.sh` for local builds (LOW).** Task 17 (version bump) ran `cargo tauri build` but did NOT first run `bash scripts/build-sidecar.sh`. As a result, the locally-built `Clauge_0.7.2_universal.dmg` shipped with a stale sidecar binary (embedded `package.json` at 0.7.1) wrapped in a 0.7.2 Tauri shell. CI is unaffected — `release.yml`'s `tauri-action` honors `tauri.conf.json::build.beforeBuildCommand` which runs `bash ../scripts/build-sidecar.sh` before the cargo build. Only local-DMG users (i.e., the v0.7.2 release smoke session) hit this. Documenting the requirement avoids the trap on future patch cycles.

## Decision

Ship v0.7.3 as a focused **auto-update reliability hotfix**. Two changes, no new modules, no new dependencies:

1. **In-process restart path with explicit child-kill** (`ipc::restart_app` IPC + `public/app.js` "Restart Now" button). The button surfaces in Settings → Updates after `check_for_updates` returns `Installed`. Clicking it: signals shutdown, kills all registered children, sleeps 200 ms (lets SIGKILL land), calls `app.restart()`. Tauri's restart replaces the process with a fresh exec of the on-disk binary, picking up the new `.app` bundle including the new sidecar binary.
2. **Cold-launch self-heal in `port_discovery::discover`** (the safety net). When `discover` finds `External(port)`, it now ALSO queries `/api/health`, parses the version field, and compares to `env!("CARGO_PKG_VERSION")`. On mismatch (or missing field, or malformed JSON), kill the PID listening on that port via `lsof -i :PORT -t` + `kill -9`, sleep 300 ms, retry `discover`. Catches every orphan-sidecar scenario regardless of which restart path the user took.

Plus: **two-line addendum to v0.7.2 plan Task 17** noting the `bash scripts/build-sidecar.sh` requirement for local builds. Not an amendment to a shipped plan (that would be misleading) — a "lessons learned" footnote.

**Considered and rejected:** a pre-update child-kill in `check_for_updates` (before `download_and_install`). Net effect would be ~1 s of sidecar unavailability followed by an immediate supervisor respawn — the supervisor sees the killed child as a natural-termination event and respawns from the OLD binary path (which is still on disk; `download_and_install` hasn't run yet). The respawned child serves the same stale version the original would have. Pure noise; dropped.

**v0.7.3 stays ad-hoc-signed** — same as v0.7.0 / v0.7.1 / v0.7.2. Apple Developer ID signing remains v0.8.0's job.

## Scope

### Adds (Rust)

- `src-tauri/src/ipc.rs::restart_app` (new `#[tauri::command] async fn`):
  ```rust
  #[tauri::command]
  pub async fn restart_app(
      state: State<'_, AppState>,
      app: tauri::AppHandle,
  ) -> Result<(), String> {
      state.signal_shutdown();
      for child in state.take_all_children() {
          let pid = child.pid();
          if let Err(e) = child.kill() {
              log::warn!("restart_app: failed to kill sidecar pid={}: {}", pid, e);
          } else {
              log::info!("restart_app: killed sidecar pid={}", pid);
          }
      }
      tokio::time::sleep(std::time::Duration::from_millis(200)).await;
      app.restart();  // never returns
  }
  ```
- `src-tauri/src/port_discovery.rs::version_matches_self` helper (new private fn, unit-testable):
  ```rust
  fn version_matches_self(health_response: &str) -> bool {
      let v: serde_json::Value = match serde_json::from_str(health_response) {
          Ok(v) => v,
          Err(_) => return false,
      };
      let server_version = match v.get("version").and_then(|v| v.as_str()) {
          Some(s) => s,
          None => return false,
      };
      server_version == env!("CARGO_PKG_VERSION")
  }
  ```
- `src-tauri/src/port_discovery.rs::kill_pid_on_port` helper (new async fn):
  ```rust
  async fn kill_pid_on_port(port: u16) -> Result<(), String> {
      use tokio::process::Command;
      let lsof = Command::new("lsof")
          .args(["-i", &format!(":{}", port), "-t"])
          .output()
          .await
          .map_err(|e| format!("lsof spawn failed: {}", e))?;
      let pids: Vec<&str> = std::str::from_utf8(&lsof.stdout)
          .unwrap_or("")
          .split_whitespace()
          .collect();
      if pids.is_empty() {
          return Ok(());
      }
      for pid in pids {
          let _ = Command::new("kill").args(["-9", pid]).status().await;
      }
      tokio::time::sleep(std::time::Duration::from_millis(300)).await;
      Ok(())
  }
  ```

## Components

### `restart_app` IPC

Lives at the bottom of `ipc.rs` near `wizard_complete` / `wizard_skip`. Synchronously drains children + kills + sleeps + calls `app.restart()`. The 200 ms sleep gives SIGKILL time to deliver before the process replaces itself; otherwise a too-fast restart could leave the kill-pending child in a weird state. `app.restart()` is Tauri 2's stable API for in-place process replacement (calls `std::process::exit(0)` and re-execs the binary).

### `check_for_updates` modification

Minimal: only the return-shape change so the frontend can show "Restart Now to apply v${version}". Existing logic (download, xattr, notification, return) unchanged. No state plumbing.

The current return type is `Result<UpdateStatus, String>` where `UpdateStatus` is a unit enum (`UpToDate | Installed`). We extend `Installed` to carry the version string so the frontend can render the right label without a second call. See "Open implementation questions" item 1 for the enum-vs-tuple choice.

### `port_discovery` self-heal

`discover` currently has shape:
```rust
pub async fn discover() -> DiscoveryResult {
    if probe(DEFAULT_PORT).await {
        return DiscoveryResult::External(DEFAULT_PORT);
    }
    DiscoveryResult::SpawnAt(DEFAULT_PORT)
}
```

After this change:
```rust
pub async fn discover() -> DiscoveryResult {
    discover_with_retry(true).await
}

async fn discover_with_retry(allow_orphan_kill: bool) -> DiscoveryResult {
    if let Some(body) = probe_with_body(DEFAULT_PORT).await {
        if version_matches_self(&body) {
            return DiscoveryResult::External(DEFAULT_PORT);
        }
        log::warn!("Orphan sidecar detected on port {}: version mismatch", DEFAULT_PORT);
        if allow_orphan_kill {
            if let Err(e) = kill_pid_on_port(DEFAULT_PORT).await {
                log::warn!("Failed to kill orphan: {}", e);
            }
            // Single retry — if mismatch persists after kill, give up and spawn anyway
            return Box::pin(discover_with_retry(false)).await;
        }
        log::warn!("Orphan kill already attempted; falling through to SpawnAt");
    }
    DiscoveryResult::SpawnAt(DEFAULT_PORT)
}
```

The `allow_orphan_kill: bool` flag prevents infinite recursion if the kill silently fails (e.g., `lsof` not on PATH). After one retry, fall through to `SpawnAt` — the supervisor will fail to bind port 3456 and the crash-respawn-backoff handles it.

`probe_with_body` extends the existing `probe` to return `Option<String>` of the response body (None on timeout / non-200 / non-clauge response). Inline implementation, ~10 lines.

### `version_matches_self` helper

Pure function, fully unit-testable. Returns `true` iff the input is valid JSON AND has a `version` field AND that field equals `env!("CARGO_PKG_VERSION")`. Three failure modes (malformed JSON, missing field, mismatched value) all return `false`. The `env!` macro evaluates at compile time so the comparison is against the exact version this Tauri shell was built against.

### `kill_pid_on_port` helper

Single async function. Shell-outs to `lsof -i :PORT -t` to get PIDs (one per line, no extra columns). For each PID, runs `kill -9 PID`. Sleeps 300 ms to let port_release propagate. Errors from `lsof` (not installed, permission denied) are logged and surfaced as `Err` so the caller can decide to skip. Errors from `kill` (process already dead) are silently ignored.

### Frontend "Restart Now" button

Markup in `public/index.html` Settings → Updates pane:
```html
<div class="updates-row">
  <button id="check-update-btn" class="secondary">Check Now</button>
  <button id="restart-btn" class="primary" hidden>↻ Restart Now</button>
  <span id="update-status" class="mono">—</span>
</div>
```

Handler in `app.js`:
```js
document.getElementById('check-update-btn').addEventListener('click', async () => {
  const status = await window.__TAURI__.core.invoke('check_for_updates');
  if (status?.status === 'installed') {
    const restartBtn = document.getElementById('restart-btn');
    restartBtn.textContent = `↻ Restart Now to apply v${status.version}`;
    restartBtn.hidden = false;
  }
});

document.getElementById('restart-btn').addEventListener('click', () => {
  // Don't await — the process will be replaced before the call returns.
  window.__TAURI__.core.invoke('restart_app');
});
```

The current `check_for_updates` returns a serde-tagged enum `UpdateStatus::Installed | UpdateStatus::UpToDate`. To carry version info, extend it to `UpdateStatus::Installed { version: String }`. Or, simpler: keep the enum, return a tuple `(UpdateStatus, Option<String>)`. Decision deferred to implementation; the frontend contract is just "I can read `status.status` and `status.version` from the response".

## Data flow

### Flow A: User-triggered update + restart (happy path)

```
1. User clicks Settings → "Check Now" (or Menu Bar → Check for Updates)
2. check_for_updates IPC fires:
   a. updater.check() → Some(update v0.7.4)
   b. update.download_and_install() — replaces /Applications/Clauge.app
   c. xattr quarantine strip (existing)
   d. macOS notification "Updated to v0.7.4. Restart to apply." (existing)
   e. Returns UpdateStatus::Installed { version: "0.7.4" }
3. Frontend receives Installed → unhides "Restart Now" button + sets label
4. User clicks "↻ Restart Now to apply v0.7.4"
5. restart_app IPC:
   a. signal_shutdown() — sets shutting_down flag + notify_waiters
   b. take_all_children().kill() — drops the live sidecar
   c. sleep 200 ms (let SIGKILL land)
   d. app.restart() — process replaces itself via re-exec from new .app
6. Fresh Tauri shell starts → port_discovery::discover() → probe finds nothing
   on 3456 (children killed in 5b) → SpawnAt(3456) → supervisor spawns fresh
   sidecar v0.7.4 → /api/health returns 0.7.4 → Settings shows v0.7.4
```

### Flow B: Cold launch with orphan sidecar (defense-in-depth)

```
1. User opens /Applications/Clauge.app (running v0.7.4 binary)
2. Tauri setup() → port_discovery::discover()
3. probe_with_body(3456) → Some(body) — orphan sidecar (v0.7.3 from previous
   install) is alive, responds with {"version":"0.7.3", ...}
4. version_matches_self("0.7.3" body) → false (env!("CARGO_PKG_VERSION") = "0.7.4")
5. log::warn!("Orphan sidecar detected on port 3456: version mismatch")
6. kill_pid_on_port(3456):
   a. lsof -i :3456 -t → "23131\n"
   b. kill -9 23131
   c. sleep 300 ms
7. discover_with_retry(false) re-runs:
   a. probe_with_body(3456) → None (port free now)
   b. Returns SpawnAt(3456)
8. Supervisor spawns fresh sidecar v0.7.4 → /api/health returns 0.7.4
```

### Flow C: Restart Now without an update (idempotent / harmless)

User shouldn't see this — the button is hidden by default. But if invoked: `restart_app` runs, kills children, restarts. Same v0.7.X relaunches. No harm done. Defends against malicious DevTools tinkering or similar.

### Flow D: lsof not installed (paranoia case)

```
1. Cold launch with orphan
2. discover finds External + version mismatch
3. kill_pid_on_port: lsof spawn fails with "command not found"
4. log::warn!("Failed to kill orphan: lsof spawn failed: ...")
5. discover_with_retry(false): probe still returns body (orphan still alive)
6. allow_orphan_kill=false → log "kill already attempted" → fall through to SpawnAt
7. Supervisor tries to bind port 3456, fails (orphan owns it)
8. Crash-respawn-backoff: fail, retry, fail, retry... until breaker trips
9. App appears broken (no working sidecar)
```

Acceptable risk. macOS ships `lsof` by default and has since at least 10.0; it's in `/usr/sbin/lsof`. Documented in error-handling.

## Error handling

| Failure | Detection | Recovery |
|---|---|---|
| `take_all_children` returns empty (no sidecar registered) | `Vec::is_empty()` after take | No-op, proceed. Cold-launch self-heal catches subsequent orphans. |
| `child.kill()` fails | `Err` from kill() | Log warn, continue. SIGKILL on a child we own almost never fails on macOS. The cold-launch self-heal is the safety net. |
| `app.restart()` fails | Shouldn't return Err | If it somehow does, log error. Frontend will see no response. User can manually quit + reopen. |
| `lsof` not installed / not on PATH | Command spawn fails (Err) | Log warn, return Err to caller. `discover_with_retry(false)` falls through to SpawnAt. App may appear broken if orphan persists; documented above. |
| `lsof` returns no PIDs (port already free) | Empty stdout | Return Ok(()), proceed to retry discovery. |
| `lsof` returns garbled output | Non-numeric "PID" | `kill -9` errors silently, port stays bound. Single retry then fall through. |
| `kill -9` fails (process already dead, or not ours) | Non-zero exit | Silently ignored — process may have died on its own, or it's owned by another user (rare on single-user macOS). |
| `/api/health` JSON malformed | `serde_json::from_str` returns Err | `version_matches_self` returns false → assume mismatch → kill orphan. |
| `/api/health` missing `version` field | None after `.get()` | Same: false → kill. |
| `/api/health` returns 200 but empty body | Empty string in `version_matches_self` | False → kill (treat as malformed). |
| User clicks Restart Now BEFORE Installed (button race) | Button hidden by default; only unhidden after `Installed` received | Cannot happen via UI. |
| `check_for_updates` called with no AppState managed (test scenario) | `State` extraction fails at Tauri layer | IPC returns error; frontend shows generic failure. Real production has AppState managed in `lib.rs::run`. |

**Crucial invariant:** version-mismatch detection ONLY runs on `External` discovery. The normal `SpawnAt` path is unchanged — every fresh sidecar we spawn is by definition matching.

## Open implementation questions

1. **`UpdateStatus` payload shape:** to carry version to the frontend, options are (a) extend the enum: `Installed { version: String }`, (b) return tuple `(UpdateStatus, Option<String>)`, (c) emit a Tauri event `update-installed` with version. Decision deferred to implementation. Recommend (a) — simplest, single-responsibility.

2. **Restart Now button styling:** "primary" (blue, prominent) or "secondary" (subdued)? Recommend primary — it's the recommended action after install. Match the wizard's primary button style for consistency.

3. **Should `kill_pid_on_port` also try `pkill -f clauge-server`?** Belt-and-suspenders approach. Plan implementation: `lsof + kill -9` is sufficient and surgical. Avoid `pkill -f` because it could kill UNRELATED processes that match the substring (e.g., a developer running a custom `clauge-server-dev`). Decision: stick with lsof.

4. **What if `app.restart()` doesn't kill the sidecar BEFORE relaunching?** The `restart_app` IPC explicitly kills BEFORE calling `app.restart()`. The 200 ms sleep gives SIGKILL time to deliver. After that, `app.restart()` re-execs the binary. The new process has a fresh PID; the (now-dead) sidecar's port should be free. Tested empirically in manual smoke step 3.
