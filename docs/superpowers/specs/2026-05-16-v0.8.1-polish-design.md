# Design: First-Impression Polish (Clauge v0.8.1)

**Date:** 2026-05-16
**Author:** brainstorming session (post-v0.8.0 ship + Windows smoke discovery)
**Status:** approved, ready for implementation plan
**Target version:** v0.8.1
**Scope:** Both platforms (macOS DMG + Windows NSIS). Single distribution channel matches v0.8.0. No Apple Developer enrollment, no MAS work, no Authenticode, no new architecture. Pure polish release.
**Sequencing:** v0.8.0 (shipped 2026-05-16, Windows port) → **v0.8.1 (this spec)** → v0.8.2 or v0.9.0 (TBD — likely WebView2 cookie capture investigation for Architecture A on Windows OR Edge add-ons store listing for Clauge Sync)

---

## Problem

v0.8.0 shipped Clauge to Windows successfully, but post-ship smoke surfaced four user-facing issues that, individually small, collectively make the first-launch experience feel unfinished:

**Problem 1 — "Page not loaded, please refresh" flash on first launch (HIGH, Windows-pronounced).** When the user clicks Clauge for the first time on Windows, the Tauri WebView opens and immediately tries to load `http://127.0.0.1:3456/`. The Node-SEA sidecar is still booting (~2-4s first time on Windows because SEA extraction is slow), so WebView gets `ERR_CONNECTION_REFUSED` and renders its default error page. After the sidecar comes up, WebView auto-retries and the dashboard appears. Net effect: 2-4 seconds of an alarming "broken page" UI before the dashboard renders. The TODO at `src-tauri/src/windows.rs:23-29` predicts this exact problem and lists "splash" as the documented mitigation. On Mac the sidecar boots in ~200-500ms so the same race occurs but is mostly invisible.

**Problem 2 — claude.ai row UX feels alarming on Windows even when extension is providing plan data (MEDIUM, Windows-only).** v0.8.0 shipped with a Windows path that hides the claude.ai Sign-in button (Architecture A is deferred) but leaves the row visible with an orange/red dot and text "Not yet supported on Windows — install Clauge Sync below for plan-ring data." Once the user installs Clauge Sync and plan data starts flowing, the dot stays orange/red, reading like a broken connection even though everything is working as intended.

**Problem 3 — Wizard "Connect" lands on Overview tab instead of Settings → Connections (MEDIUM, both platforms).** After the first-launch wizard completes its credential read, the dashboard surfaces but stays on the default Overview tab. The user has just finished a 4-step setup flow and has no immediate signal that their connection state succeeded; they have to navigate to Settings → Connections themselves. Lost teaching moment.

**Problem 4 — Wizard never prompts user to install Clauge Sync (MEDIUM, Windows-required, Mac-recommended).** Clauge Sync (the Chrome Web Store extension at ID `ailfbgegpplecgcadlkplkllobepfcga`) is the only path to plan-ring data on Windows (claude.ai sign-in is deferred). v0.8.0's plan-capacity empty-state walkthrough explains *how* to install it but only appears if the user navigates to a specific dashboard section. Most Windows users never see it. Mac users also benefit from the extension as a complement to claude.ai sign-in.

Plus two carryover items from the v0.7.x deferred list, bundled because we are touching the codebase:

**Problem 5 — Font 404s in production builds (LOW).** `public/styles.css` references `inter-latin-variable.woff2` and `jetbrains-mono-latin-variable.woff2` but neither file is present in the SEA asset manifests (`sea-config.json` + `scripts/sea-bootstrap.cjs` ASSETS array per memory `reference_sea_manifest_mirror.md`). Browsers fall back to system fonts silently; the 404s log noise in dev-tools network panel.

**Problem 6 — `probe` / `probe_with_body` near-duplicate in `port_discovery.rs` (LOW).** v0.6.0 reviewer flagged it as Task 3 follow-up. `probe()` could delegate to `probe_with_body(port, None)`. Resolves a `dead_code` warning and removes ~25 lines of duplicated function body. No behavior change.

## Decision

Ship v0.8.1 as a focused **"first-impression polish" release**. Six changes, no new modules, no new dependencies, no new Tauri permissions:

1. **Splash screen replaces the "page not loaded" flash.** New `popover/splash.html` loaded via `WebviewUrl::App("splash.html".into())` (instant, served from Tauri's bundled assets — the popover/ directory is already `frontendDist`). Rust emits Tauri event `sidecar-ready { port: u16 }` when `/api/health` first returns 200; splash JS listens and `window.location.href`s to the dashboard. Timeout fallback: 30s without a `sidecar-ready` event → splash shows "Failed to start Clauge" + Restart App button (reuses existing `restart_app` IPC).
2. **claude.ai row UX de-alarmed when extension is active.** Windows: row hidden entirely when `status.extension === 'active'` (sign-in is deferred anyway, no useful controls left). Mac: when `status.extension === 'active'` AND `status.claude_ai === 'not_connected'`, render row in a new neutral `optional` state (gray dot, text "Optional — plan data is flowing via Clauge Sync") so the user still has visible sign-in/out access if they want it.
3. **Wizard Connect → Settings/Connections.** `wizard_complete` IPC emits Tauri event `navigate-to-connections`; dashboard's app.js listens and switches tabs. `wizard_skip` unchanged (lands on Overview, matches "let me into the app" intent).
4. **New wizard step "Install Clauge Sync"** between current Permissions (step 3) and Connect (current step 4, becomes step 5). Big "Install Clauge Sync" button opens `https://chromewebstore.google.com/detail/clauge-sync/ailfbgegpplecgcadlkplkllobepfcga` via `shell.open` (works for Chrome AND Edge; Edge supports installing from Chrome Web Store with a one-time toggle). Wizard auto-advances to Connect when the extension's first heartbeat arrives via `get_connection_status` IPC (polled every 5s while on step 4). Already-installed users (heartbeat < 90s old on step entry) see "Already installed ✓" + auto-advance after 1s. Skip-for-now link available for users who decline.
5. **Font 404 fix.** Add `inter-latin-variable.woff2` and `jetbrains-mono-latin-variable.woff2` to both SEA manifests + commit the actual font files under `public/fonts/`.
6. **`probe` dedup.** `probe(port)` becomes a thin wrapper around `probe_with_body(port, None)`.

**Extension-active threshold: keep existing 10 minutes.** `connections.rs:9` already defines `EXTENSION_FRESHNESS_MINUTES = 10` and the existing `compose_status` function maps the heartbeat timestamp to `ConnectionState::Active` or `NotDetected` based on this constant. v0.8.1 reuses the existing constant unchanged. 10 minutes is forgiving (handles Chrome tab sleep, brief network blips, laptop wake-from-sleep) while still going stale fast enough that a removed/disabled extension shows correct state within an upper-bound window. The extension polls every 1 minute (`extension/background.js:194`), so during normal operation the timestamp refreshes well within the threshold. **Threshold is enforced in Rust** (existing v0.8.0 behavior), inside the `compose_status` helper — frontend code reads the `ConnectionState::Active` / `NotDetected` enum without caring about timing. The frontend's `IS_WINDOWS && status.extension === 'active'` check naturally inherits this 10-minute window.

**Considered and rejected:**

- **"Block window creation until sidecar is healthy"** (alternative to splash). Pros: simpler, no new HTML. Cons: user sees ~2-4s of literally nothing happening on Windows ("did the app even launch?"). Splash gives the same wait window a branded, intentional feel. Splash wins on UX for equivalent implementation effort.
- **"Hide the claude.ai row entirely on Mac when extension is active"** (alternative to neutral gray). Cons: Mac has working Architecture A sign-in; hiding the row removes user access to Sign-In/Sign-Out controls. Neutral gray (option C from brainstorming) preserves access while de-alarming.
- **"Show claude.ai row as green when extension is active"** (Option B from brainstorming — the user's initial intuition). Cons: misrepresents reality. claude.ai itself is not signed in; the extension is the actual data source in its own row. Green would lie about state.
- **"WebView2 cookie capture investigation for Architecture A on Windows"** as part of v0.8.1. Pro: would actually fix the underlying claude.ai sign-in issue on Windows. Con: multi-day investigation, no guarantee of success (WebView2 cookie semantics differ from WKWebView). Defer to v0.8.2+ or v0.9.0 if a real user need surfaces.
- **"Edge add-ons store listing for Clauge Sync"** alongside Chrome Web Store. Pro: cleanest path for Edge users (no "allow from other stores" toggle). Con: separate publish workflow, separate review cycle. Deferred. One Web Store URL works for both Chrome AND Edge today — Edge auto-rewrites "Add to Chrome" to "Add to Edge" after the user enables third-party stores once.
- **"Authenticode signing on Windows"**. Cost (~$300-500/yr EV cert + HSM/USB token) vs current install volume doesn't justify yet. v0.8.x stays unsigned with documented SmartScreen click-through.

**v0.8.1 stays on the same distribution channel as v0.8.0** — auto-updater via gh-pages `latest.json`, same minisign key, same NSIS perUser install path on Windows.

## Scope

### Adds (frontend)

- `popover/splash.html` (new file, ~40 lines) — minimal HTML with embedded Clauge logo SVG + spinner + "Starting Clauge…" copy.
- `popover/splash.css` (new file, ~60 lines) — centered layout, oklch-based color tokens matching dashboard's existing design system, dark/light aware via `prefers-color-scheme`.
- `popover/splash.js` (new file, ~50 lines) — Tauri event listeners for `sidecar-ready` (navigate to dashboard URL from event payload) and `sidecar-failed` (show retry UI). Fallback path if `sidecar-ready` event never fires within 5s: invoke the existing `get_server_port` IPC (already in `ipc.rs:140`, returns `Result<u16, String>` — `Ok(port)` once port is set, `Err("server port not yet set")` while still booting). If it returns Ok, navigate; if Err, keep waiting up to the 30s timeout. We use IPC rather than cross-origin fetch from `tauri://localhost` to `http://127.0.0.1:{port}/api/health` to sidestep CORS (the sidecar's Hono server does not set CORS headers for the tauri:// origin).

### Adds (wizard)

- New `<section data-step="4" class="wizard-step">` in `public/onboarding/index.html` between current `data-step="3"` (Permissions) and current `data-step="4"` (Connect, which becomes `data-step="5"`). Contents:
  - Title: "Install Clauge Sync"
  - 64×64 Clauge Sync icon SVG
  - Platform-conditional copy via `.platform-mac` / `.platform-win` divs (existing v0.8.0 pattern)
  - Primary button: `[data-install-extension]` "Install Clauge Sync"
  - Secondary link: `[data-skip-step]` "Skip for now"
  - Status indicator: `<p class="install-status" data-status="idle">` with text-swap states (idle / waiting / installed / already-installed)
- `public/onboarding/onboarding.js` additions:
  - `TOTAL_STEPS` constant: `4 → 5`
  - `CLAUGE_SYNC_WEB_STORE` constant: `'https://chromewebstore.google.com/detail/clauge-sync/ailfbgegpplecgcadlkplkllobepfcga'`
  - New `pollExtensionStatus()` function — interval-based (5s) call to `get_connection_status` IPC; stops on step transition out of step 4
  - New `onStepEntered(n)` hook — when `n === 4`, immediately fetch status (already-installed shortcut), else start poll
  - New click handlers: `[data-install-extension]` → `shell.open(CLAUGE_SYNC_WEB_STORE)` + update status to "waiting"; `[data-skip-step]` → `showStep(5)` immediately
- `public/onboarding/onboarding.css` additions:
  - `.install-status[data-status="idle"|"waiting"|"installed"|"already-installed"]` text + color variants
  - `.install-extension-btn` styling consistent with existing `.wizard-btn-primary`
  - Pulse animation for "Waiting for installation…" status

### Adds (Rust)

- `src-tauri/src/sidecar.rs` — inside the existing supervisor loop, after the spawned `clauge-server` first responds 200 to `/api/health`, emit Tauri event `sidecar-ready` with payload `{ port: u16 }`. After 30s of failed health checks (configurable constant — bumped during dev if needed), emit `sidecar-failed` with payload `{ error: String }`. The supervisor already tracks the port (set via `AppState.set_port`); event emission piggybacks on the existing successful-startup path.
- `src-tauri/src/ipc.rs::wizard_complete` — at the end of the existing handler (after credential read), emit Tauri event `navigate-to-connections` (no payload).

### Modifies (frontend)

- `public/connections.js::applyStatus` — two new branches (must handle BOTH directions so state toggles correctly when extension transitions active ↔ inactive):
  - Windows hide/show: `const hideOnWindows = IS_WINDOWS && status.extension === 'active'; claudeAiRow.hidden = hideOnWindows;`. When `hideOnWindows` is true, skip the claude.ai applyRow call. When false (Mac always, Windows when ext inactive), claudeAiRow.hidden gets set back to false and applyRow runs normally — so extension going inactive on Windows re-shows the row with the v0.8.0 alarm state, which is correct (the user IS now disconnected).
  - Mac neutral-gray override: if `!IS_WINDOWS && status.extension === 'active' && status.claude_ai === 'not_connected'`, override `status.claude_ai = 'optional'` before applyRow. If Mac user IS signed in to claude.ai while extension is also active, no override fires; row shows green "Signed in" (v0.8.0 behavior, both sources active is fine).
- `public/connections.js::STATE_LABELS.claude_ai` — add new key: `optional: 'Optional — plan data is flowing via Clauge Sync'`.
- `public/connections.js::A11Y_DOT_LABEL` — add new key: `optional: 'optional'`.
- `public/connections.js` — new constant `CLAUGE_SYNC_WEB_STORE` (same URL as wizard) + click handler on existing extension-row "Install Clauge Sync" CTA element (.conn-cta) that calls `shell.open(CLAUGE_SYNC_WEB_STORE)`.
- `public/styles.css` — new dot color rule: `.conn-row[data-state="optional"] .conn-dot { background: oklch(60% 0 0); }` (mid-gray, theme-aware via existing oklch tokens).
- `public/app.js` — new Tauri event listener: `window.__TAURI__.event.listen('navigate-to-connections', () => { switchTab('settings'); document.querySelector('.set-side button[data-set="sync"]')?.click(); })`. Reuses the existing `switchTab` function at `app.js:783` plus the existing Settings sub-nav click handler at `app.js:804` (which already toggles `[data-set-panel]` visibility). **Note:** the Connections sub-panel's attribute is `data-set="sync"` (legacy name from the v0.5.x extension-autodetect era; the user-facing label is "Connections"). The sub-panel element is `<div class="set-section" data-set-panel="sync">` at `index.html:406`. Two-step navigation (top-level Settings tab + Connections sub-panel) matches how a user navigates manually.

### Modifies (Rust)

- `src-tauri/src/windows.rs::create_dashboard` — change initial URL from `WebviewUrl::External(http://127.0.0.1:{port}/)` to `WebviewUrl::App("splash.html".into())`. Relax `on_navigation` handler to also allow `tauri://localhost/*` for the initial splash load (otherwise Tauri blocks even loading splash.html). New allow check: `(scheme == "tauri" && host == "localhost")` OR `(scheme == "http" && host in [127.0.0.1, localhost] && port == live_port)`.
- `src-tauri/src/port_discovery.rs::probe` — refactor to delegate to `probe_with_body(port, None)`. Existing 47 unit tests verify equivalence.

### Modifies (build)

- `sea-config.json` — append `public/fonts/inter-latin-variable.woff2` and `public/fonts/jetbrains-mono-latin-variable.woff2` to `assets` map.
- `scripts/sea-bootstrap.cjs` — append the same two paths to the `ASSETS` array.

### Adds (assets)

- `public/fonts/inter-latin-variable.woff2` — Inter Variable woff2, latin subset, latest stable from rsms/inter releases.
- `public/fonts/jetbrains-mono-latin-variable.woff2` — JetBrains Mono Variable woff2, latin subset, latest stable from JetBrains/JetBrainsMono releases.

### Unchanged (verified)

- Sidecar HTTP protocol (`/api/health`, `/api/usage/ingest`, all dashboard endpoints)
- Auto-updater plumbing (`latest.json`, minisign signing, gh-pages mirror)
- Build matrix in `release.yml` (Mac universal + Windows x86_64)
- Existing Tauri permissions (`shell:allow-open` from v0.8.0 iter 8 covers Web Store URL open)
- Existing wizard steps 1, 2, 3 (Welcome, Reading Credentials, Permissions) — unchanged except renumbering of step 4 → step 5
- Existing 47 Rust unit tests + 109 Node tests
- Existing keychain reader, credential cache, port-discovery contract

## Open questions

- **Splash → dashboard navigation handler.** Need to verify in implementation that Tauri's `on_navigation` handler fires for the initial `tauri://localhost/splash.html` load. If yes, the relaxed allow check above is required. If no (Tauri's internal asset load skips `on_navigation`), only the splash → external `http://127.0.0.1:{port}/` redirect needs whitelisting (already allowed by current handler since destination is localhost+port). Implementation plan should test this early in Task 1.
- **Splash → dashboard race on slow Mac dev.** `sidecar-ready` fires once `/api/health` returns 200. On Mac dev (cargo tauri dev — `frontendDist` files not bundled, sidecar served from `npm run dev` instead), splash might load before sidecar even starts. Mitigation: splash falls back to direct `/api/health` polling if `sidecar-ready` doesn't fire within 5s. This is the same defense-in-depth case as production timeout, just with a faster trigger.
- **Wizard auto-advance race during step 4.** If user clicks "Install Clauge Sync" and the Web Store install completes faster than expected (~10s), the auto-advance fires while user is still reading. 1s grace window ("Installed ✓ Continuing…" displayed) before `showStep(5)` provides minimum perception time. Acceptable.

## Risks

- **Splash navigation handler change could break existing `target="_blank"` external URL handling.** Mitigation: the `on_new_window` handler for `target="_blank"` is separate from `on_navigation` (different Tauri lifecycle hook). Adding a `tauri://` allow case to `on_navigation` doesn't touch `on_new_window`. Verify by manual smoke of external URL buttons after Task 1 lands.
- **Splash CSS dark/light mode might not match dashboard's exact tokens.** Mitigation: use the exact oklch values from `public/styles.css` `:root` and `[data-theme="dark"]` blocks. Splash should look like a natural pre-state of the dashboard, not a different design system.
- **Wizard renumbering risk.** Changing `data-step="4"` → `data-step="5"` in HTML must match `TOTAL_STEPS = 5` in JS and the `<progress max="5">` attribute. Off-by-one risk if any one missed. Mitigation: grep for `data-step="` and `TOTAL_STEPS` before commit; cargo test would not catch this.
- **Font 404 fix could mask a CSS bug.** If the woff2 files are added but the `@font-face` declarations in styles.css use wrong `format()` hint or wrong unicode-range, fonts still don't apply. Mitigation: after adding files, verify in Mac dev tools that Inter / JetBrains Mono actually render (not system fallback) on the dashboard.

## Success criteria

- Cold-launch on Windows VM: click Clauge → branded splash visible within 200ms → dashboard rendered with no "page not loaded" flash.
- Cold-launch on Mac: same behavior (less visible because sidecar boots fast, but no regression).
- Fresh install + first-launch wizard: walk through 5 steps → step 4 shows Install button → click Install → Web Store opens → install Clauge Sync extension → wizard auto-advances to step 5 within ~30s of install completion → click Connect → dashboard lands on Settings → Connections tab with all three rows showing correct state.
- Wizard with already-installed extension: step 4 shows "Already installed ✓" → auto-advance to step 5 after ~1s.
- Wizard with user clicking "Skip for now" on step 4: advance to step 5 immediately.
- Wizard Skip-everything (Skip on any step): dashboard lands on Overview, not Connections.
- claude.ai row UX (Windows, extension active): row not visible in Connections panel.
- claude.ai row UX (Mac, extension active, not signed in): row visible with gray dot + "Optional — plan data is flowing via Clauge Sync" text.
- claude.ai row UX (Mac, extension active, signed in): row visible with green dot + "Signed in to claude.ai" text (existing v0.8.0 behavior, unchanged).
- claude.ai row UX (either platform, extension not active): existing v0.8.0 behavior, unchanged.
- Network tab after dashboard load: zero 404s on `inter-latin-variable.woff2` or `jetbrains-mono-latin-variable.woff2`.
- Inter and JetBrains Mono fonts render correctly (not system fallback) on dashboard.
- `cargo test --locked --lib` passes 47 tests on both Mac and Windows.
- `npm test` passes 109 tests on Mac (Windows skips SIGTERM suite per v0.8.0).
- v0.8.1 GitHub Release published with Mac DMG + Windows NSIS installer + `latest.json` updated to 0.8.1.
- gh-pages `latest.json` mirror shows version=0.8.1 with all 6 platform keys.
- Mac v0.8.0 auto-update detects v0.8.1 and offers the update (no manual reinstall required).

## Ship strategy

Single branch (`clauding-lab/v081-polish` or equivalent), single PR or direct fast-forward to main following v0.8.0's established pattern, single CI cycle (build matrix in `release.yml` already covers Mac + Windows). Tag v0.8.1 after Windows VM smoke confirms splash + wizard nav + extension install flow + Mac auto-update path.

Subagent dispatches use Opus on every call (per memory `feedback_subagent_model.md`). Implementer + spec reviewer + code quality reviewer pattern from v0.7.x / v0.8.0 continues.
