## 1. Mission (rev 4)

Clauge ships three surfaces today: Mac menu-bar app, iOS companion, Windows app. This adds the **fourth: the Clauge Widget** — a complete, self-contained Claude Code statusline rendered by **`clauge status`**, wired directly as the `statusLine` command in `~/.claude/settings.json`. It replaces third-party statusline tools outright (Adnan will uninstall ccstatusline when this ships and expects users to do the same): the widget owns every line — working context (model, path, code churn, runtime, branch), quota gauges, spend + ROI, and session hygiene (context fill + compactions). A machine-readable `clauge status --json` serves scripts and Mission Control from the same verb.

Rationale (from the aiusage dissection, `docs/why.md` of that repo): the native statusline signal vanishes when no Claude Code terminal is open, and per-render network polling 429s — so the winning architecture is *daemon owns the data, render path reads a local cache*. Clauge already IS that daemon; this widget is a thin client on the existing loopback HTTP surface plus the session payload Claude Code pipes to statusline commands on stdin.

## 2. Measured facts (2026-07-16, Adnan's MacBook Pro M5 Pro, installed production Clauge.app v1.3.3, sidecar live on port 3456)

These are real numbers from the shipped app, not estimates:

1. **SEA cold-start is a non-issue on Apple Silicon:** `/Applications/Clauge.app/Contents/MacOS/clauge-server config get` = **86–91 ms end-to-end** (5 runs: 90/91/86/89/88), *including* SEA asset extraction (~1.5 MB / 28 files, `scripts/sea-bootstrap.cjs:37-66` ASSETS list, extraction loop `:68-75`), the HTTP round-trip to the live sidecar, and JSON print. Well inside a ~300 ms statusline budget. Caveat: M5 Pro + APFS + warm cache; measure separately on Windows/older Intel Macs before assuming. **Re-verified 2026-07-17 (two independent passes):** warm runs 40–103 ms, exit 0 — conclusion holds. BUT the first **cold** invocation (empty SEA extraction cache, e.g. right after reboot) measured **1.6 s wall** (~50 ms CPU + ~1.55 s I/O): `scripts/sea-bootstrap.cjs:68-75` re-extracts all 28 assets (~1.5 MB, incl. fonts/HTML the CLI never uses) to a **fresh temp dir on every invocation** — there is no cross-invocation cache; the warm speed comes from OS page/disk caches, not app logic. Design consequences: (a) a statusline's first post-boot render can blow the ~300 ms budget ~5×, so the render path should read the §4 stale-cache first and treat HTTP+SEA as the refresher; (b) any latency claim for a continuously re-invoked statusline needs a repeated-invocation benchmark, not a single-shot timing; (c) best-effort temp cleanup can leak dirs on SIGKILL (landmine #31) — worth a periodic sweep or a cheaper dedicated entry path.
2. **The shipped Mac CLI wrapper is BROKEN — two path bugs (P0 prerequisite, §5):** the wrapper lands at `Contents/Resources/Resources/clauge-cli` (Tauri nests the `resources` dir) but resolves the binary as `$DIR/../MacOS/clauge-server-aarch64-apple-darwin` → (a) wrong depth (`Resources/MacOS/` doesn't exist) and (b) wrong name — the installed bundle ships `Contents/MacOS/clauge-server` *unsuffixed* (Tauri strips the target-triple for `externalBin` at bundle time). Observed output: `clauge: bundled sidecar not found at /Applications/Clauge.app/Contents/Resources/Resources/../MacOS/clauge-server-aarch64-apple-darwin`, exit 1. **No user has ever successfully run the bundled CLI.** Beware: a broken-wrapper invocation fails in ~31 ms — fast timings can masquerade as success; always check exit code + output.
3. **`which clauge` → not found** on a machine that has run Clauge daily for weeks — the `install_cli_symlink` flow (macOS impl `src-tauri/src/ipc.rs:949-1000`; the `:940-947` range is the non-macOS stub) is opt-in and effectively never invoked.
4. **The Homebrew cask does NOT put `clauge` on PATH:** `clauding-lab/homebrew-tap` `Casks/clauge.rb` (v1.3.3) contains only `app "Clauge.app"` — no `binary` stanza. `README.md:137`'s claim "Homebrew installs put `clauge` on PATH automatically" is **false**. Fix is a one-line cask change (separate repo) or a README correction. (Re-confirmed 2026-07-17 via `brew cat clauding-lab/tap/clauge` on the locally-synced tap: cask v1.3.3 contains `app "Clauge.app"` only — no `binary` stanza.)

## 3. Where the code goes (recon summary, all verified)

- **Dispatcher:** `lib/cli/index.js`. `parseArgs` (`:42-76`) and `runCli` (`:121-162`, returns exit code, **never** calls `process.exit` — caller `server.js:64` owns exit). Exit codes: 0 success / 1 runtime failure / 2 usage error (`:118-119`).
- **Adding the verb (exact steps, matches `AGENTS.md:256-259`; rev 4 — ONE verb, `status`, with `--json`/`--install` as flags):** (1) add an `if (parsed.verb === 'status')` branch in `runCli` before the unknown-verb tail (`:159`), dynamic-importing `./status.js` (convention: `:147-148`). (2) Add to `printUsage` (`:78-98`). (3) Test file **must** live under `test/cli/` — the `npm test` glob is `test/*.test.js test/cli/*.test.js` (`package.json:19`, `AGENTS.md:271`); a third dir is silently skipped. (4) Subverbs for new verbs require extending `parseArgs` line 50 (currently `config`-only) — not needed for flag-only commands.
- **Data access pattern to copy:** `buildConfigOutput` (`lib/cli/config-get.js:48-57`) — read port via `readActivePort()` (`:21-29`, uses `configPaths.portFile()` `lib/config-paths.js:97`, **never hardcode 3456**; fallback binding shifts ports to 3457–3460) → HTTP GET `http://127.0.0.1:${port}/...` → on ANY failure fall through gracefully. Use `fetchWithTimeout` (`lib/http.js:16-24`) with the injectable `fetchImpl` seam for tests.
- **Timeout:** existing CLI uses 2000 ms (`config-get.js:19`) — too slow for a statusline. Use **250 ms** with fail-fast degrade (measured round-trip is ~90 ms total, so 250 ms is ~3x headroom).
- **Data source:** prefer `GET /v1/usage` (companion doc) once shipped; until then `GET /api/snapshot` (`server.js:653-672`) — `buildSnapshot` (`lib/snapshot.js:296-319`) already packages `roi`, `summary.cost`, `usage.plan` ideal for a one-liner. Optional compat check: `GET /api/health` returns `{service:'clauge', version}` (`server.js:266-277`).
- **ANSI is net-new to this codebase** (zero color/`isTTY`/`NO_COLOR` precedent in `lib/` — verified by grep; no chalk dependency and none should be added). The statusline command therefore *defines* the convention: emit ANSI by default (statusline hosts want it), suppress when `NO_COLOR` is set or `--plain` is passed. Keep the renderer dependency-free (raw escape codes like aiusage's `statusline.py`).

## 4. Command design (rev 4 — render contract LOCKED with owner, 2026-07-18)

### `clauge status`
Three lines to stdout, exit 0 **always** (a statusline must never error-spam the host). The locked render, shown with the real data it was designed against:

```
Opus 4.8 · ~/Projects/clauge · +267/-0 · ⧗ 42m · main
Session ▓▓░░░░░░░░ 20% (resets 2h) · Weekly ▓░░░░░░░░░ 9% (resets 5d)
$664 this window · ROI 17.3× vs API · Context Used 46% · Compactions 0
```

**Locked contract (owner decisions, 2026-07-18):**
1. **Line 1 — working context:** model (magenta) · working path (blue) · lines added/removed this session (green `+` / red `−`) · session runtime `⧗` (cyan) · git branch (magenta). No leading glyph on any line; labels are full words, never `S`/`W` abbreviations.
2. **Line 2 — quota gauges:** `Session` and `Weekly`, each as a 10-cell `▓░` bar + percent + `(resets …)`.
3. **Line 3 — value + hygiene:** spend `$` and ROI figure in **yellow** (yellow is reserved for money, nothing else) · `Context Used %` · `Compactions N`.
4. **Thresholds — gauges:** Session, Weekly, and Context Used each color **independently** on their own value: green below 75%, **orange at ≥75%**, **red at ≥90%**. Orange is the warning tier only — never reuse it for money, and never collapse it into yellow: emit 256-color/truecolor orange (e.g. `\e[38;5;208m`) with plain yellow ANSI as the last-resort fallback on 8/16-color terminals.
5. **Thresholds — compactions:** own scale: green at 0, orange at 1, red at 2+ (a multiply-compacted session is due for a save + fresh session — the harness-audit hygiene rule, now ambient).
6. **Data sources (this changed in rev 4 — stdin is now load-bearing):**

| Segment | Source |
|---|---|
| Model, path, lines +/−, runtime, Context Used | **Claude Code's stdin session payload** (piped to every statusLine invocation; `model.display_name`, `workspace.current_dir`, `cost.total_lines_added/removed`, `cost.total_duration_ms`, context fields) — parse defensively, omit a segment rather than crash on a missing field |
| Compactions | Transcript-derived (the stdin payload carries `transcript_path`; count compaction boundaries) — omit segment if unreadable |
| Git branch | `git -C <current_dir> branch --show-current` with a short timeout — omit segment on failure/non-repo |
| Session %, Weekly %, resets, spend, ROI | **Loopback API** (`/v1/usage` once shipped, `/api/snapshot` meanwhile) via port-file discovery — the §5 degrade ladder applies to these fields only; the stdin-sourced lines render even when the app is down |

   The rev-3 "ignore stdin" rule is superseded: stdin must be **read** (non-blocking, bounded) but must never be *required* — if stdin is empty or malformed (e.g. run by hand in a shell), render line 2–3 from the API and omit the stdin-sourced segments gracefully.
- Degrade ladder: sidecar live → full line · port file present but connection fails → last-known cache (see below) or `clauge: app not running` · no port file → `clauge: app not running`. All exit 0.
- Optional tiny cache (`~/.clauge/statusline-cache.json`, write-through on success) to serve stale-but-shown when the app is briefly down — mirrors aiusage's stale discipline. Decision §9. **Rev-3 additions:** the write MUST be atomic (tmp + rename, the `config-store.js` `writeAll` pattern) — statusline invocations overlap under rapid re-render and a torn write must never corrupt the cache; the cache READ must sit in try/catch falling back to `clauge: app not running` on any parse error, or a corrupt cache breaks the exit-0-always guarantee on the exact path (app down) where it matters most.
- Flags: `--plain` (no ANSI), `--provider claude` (future-proofing), `--max-width <n>`.
- **Host-contract facts (rev 4 — the host is Claude Code's native statusLine, invoked directly):** (a) Claude Code pipes a session-context JSON payload into the command's **stdin** on every render — under rev 4 this is a load-bearing input (§4 data-source table): read it non-blocking and bounded, parse defensively, and degrade to segment omission when absent/malformed (hand-run in a shell must still work). (b) Renders recur continuously for the life of every session — the cache-first read (§4) is what keeps the per-render cost flat and absorbs the ~1.6 s cold start. (c) The line must read well **with colors stripped** — don't encode meaning in color alone (thresholds also change the number itself, not just its color… the % value is the meaning; color is emphasis). (d) exit-0-always for the render mode — a statusline host treats non-zero as breakage. (e) These constraints were originally verified against ccstatusline v2.2.23's `CustomCommand.tsx` (2026-07-17) when it was the planned host; they hold for direct Claude Code invocation, minus its host-side ANSI stripping — Claude Code renders ANSI, which is why the §4 color grammar exists.

### `clauge status --json`
Pretty-printed JSON (house style: 2-space, newline-terminated, `config-providers.js:34-37` pattern). Emit the **`/v1/usage` normalized envelope verbatim** so scripts get one schema whether they hit HTTP or CLI. When only `/api/snapshot` exists (pre-`/v1`), transform to the envelope in the CLI — the shape is the contract, the transport is an implementation detail. **Exit-code contract (deliberately DIFFERENT from the render mode):** `--json` is for scripts/Mission Control, so it exits **non-zero on fetch/parse failure** (callers must be able to detect "app not running"), while the plain render stays exit-0-always. Add a test asserting both behaviors against the same failing fetch stub.

### `clauge status --install` (rev 4: promoted from optional to CORE)
The widget is a full statusline replacement, so `--install` is the adoption path, not a convenience: it writes `statusLine: {type:"command", command:"<abs path> status"}` into `~/.claude/settings.json`, copying aiusage's civility rules exactly (its `setup.py:30-59`, re-verified from a fresh clone 2026-07-17): refuse to clobber a *different* existing statusLine without `--force`; back up first; bail untouched on invalid JSON. Replacing a previous statusline tool (e.g. ccstatusline) is the expected first-run case — the `--force` prompt should name what it's replacing so the switch is deliberate.

## 5. Prerequisite fixes (the widget is dead-on-arrival without #1)

1. **P0 — fix the bundled wrapper** (`src-tauri/Resources/clauge-cli`). Rev-3 update (2026-07-17): two independent adversarial reviews found the rev-2 recipe ("try both depths, both names") **insufficient on three counts**; all four parts below are required, in one PR:
   1. **Symlink canonicalization FIRST.** The wrapper computes `DIR=$(cd "$(dirname "$0")" && pwd)` (`clauge-cli:14`) with no `readlink`. Both PATH mechanisms this doc promises — `install_cli_symlink` (creates `/usr/local/bin/clauge → …/Resources/Resources/clauge-cli`, `ipc.rs:988`) and the PR-D Homebrew `binary` stanza — invoke the wrapper *through a symlink*, so `$0` is the symlink path, `DIR=/usr/local/bin`, and every bundle-relative probe (including "cd-up until `Contents/`") fails. Fix: POSIX readlink loop at the top (`SELF="$0"; while [ -L "$SELF" ]; do TARGET=$(readlink "$SELF"); case $TARGET in /*) SELF=$TARGET;; *) SELF=$(dirname "$SELF")/$TARGET;; esac; done; DIR=$(cd "$(dirname "$SELF")" && pwd)`), then probe relative to the real location.
   2. **Probe set must cover BOTH channel layouts.** DMG: `Contents/MacOS/clauge-server` (unsuffixed — Tauri strips the target-triple from `externalBin`, `tauri.conf.json:23`). **MAS: the sidecar is NOT in `Contents/MacOS/`** — `scripts/build-mas-clean.sh:78-80,209` moves it to `Contents/Helpers/Clauge Helper.app/Contents/MacOS/clauge-server` post-build (runtime path confirmed in `src-tauri/src/sidecar.rs:224,238-243`), while the wrapper still ships at the same nested `Resources/Resources/` spot (`tauri.mas.conf.json` overrides neither `resources` nor `externalBin`). Probes limited to `../MacOS`/`../../MacOS` leave the App Store CLI broken while testing green on a DMG install — the exact failure mode that shipped this bug. Probe both, plus the suffixed name for belt-and-braces. Whether the sandboxed Helper binary is exec-able standalone from a terminal was MEASURED during PR-A (2026-07-18): it is NOT — SIGTRAP (exit 133) at launch on the real b11 bundle, because `com.apple.security.inherit` requires a sandboxed parent. MAS is scoped out of the terminal CLI; App Store users route to `npx clauge` (§9 decision 6, now resolved).
   3. **`resolve_bundle_cli_path` is a required fix, not an audit.** It returns `contents.join("Resources").join("clauge-cli")` = the un-nested `Contents/Resources/clauge-cli` (`ipc.rs:1006-1010`) — a path that does not exist in the real bundle — so `install_cli_symlink`'s `bundle_cli.exists()` guard (`ipc.rs:954`) fails and the dashboard "install CLI" button **hard-errors 100% of the time today** ("Bundled CLI wrapper not found… Reinstall Clauge."). Fix: add the second `.join("Resources")`, correct the stale doc-comment (`ipc.rs:1002-1004`), and add a Rust unit test asserting the resolved path ends in `Resources/Resources/clauge-cli` so the nesting can't silently regress. This is NOT separable from the wrapper fix — without it, "clauge on PATH" stays impossible regardless of wrapper robustness.
   4. **Verify on installed bundles of both channels, not the repo tree** — the repo layout (`Resources/clauge-cli`) differs from the bundled layout (`Resources/Resources/clauge-cli`, from the `resources: ["Resources/clauge-cli"]` prefix-preserving copy, `tauri.conf.json:24`); that gap is exactly how this shipped broken. A DMG-only verification repeats the mistake one channel over. Candidate `AGENT_LEARNINGS.md` entry.
2. **P1 — Homebrew cask `binary` stanza** (in `clauding-lab/homebrew-tap`, separate repo/PR) pointing at the (fixed) wrapper, or correct the README. Note `README.md:136-137` carries TWO falsehoods to fix together: the Homebrew-PATH claim AND the wrapper path itself ("ships the CLI at `Contents/Resources/clauge-cli`" — actual bundled path is `Contents/Resources/Resources/clauge-cli`). Cask bumps are dispatched by `release.yml:328-367`; a manual tap PR is fine meanwhile.
3. **P2 — Windows:** no PATH story exists (`ipc.rs:940-947` hard-errors off macOS; NSIS adds nothing to PATH). Short-term: document `npx clauge status --json` for one-shot script use (the npm `bin` → `server.js` path, plain Node — no SEA tax). **Rev-3 caveat: `npx` is NOT viable per-render** — its resolution overhead alone can exceed a statusline budget/timeout, so it must not be documented as the Windows *statusline* answer; the `clauge.cmd` shim (or a globally-installed `clauge` bin) remains the real fix and stays a backlog item.

## 9. Decisions (rev 4 — most are now RESOLVED by the owner, 2026-07-18)

1. **Scope of v1 — RESOLVED:** one verb, `clauge status`, with `--json` and `--install` flags. All ship together.
2. **Stale-cache file — RESOLVED:** yes. `~/.clauge/statusline-cache.json`, atomic tmp+rename write, guarded read (§4), age label, no TTL logic. It absorbs both the cold-start timeout and the SEA extraction churn.
3. **`--install` — RESOLVED (reversed from rev 3):** CORE, not deferred — the widget is a full statusline replacement and `--install` is the adoption path (§4). Civility rules mandatory.
4. **PR-A first? — RESOLVED (2026-07-18):** owner said "go PR-A"; implemented on branch `fix/cli-wrapper-paths` (readlink loop + dual-channel probes + `resolve_bundle_cli_path` fix + unit tests; verified on the installed DMG bundle and a real MAS b11 bundle copy).
5. **Render content/branding — RESOLVED:** the §4 three-line contract is locked (full labels, no leading glyphs, magenta/blue/green-red/cyan/yellow color grammar, per-gauge 75/90 thresholds, compactions 0/1/2+). Must still read well with colors stripped.
6. **MAS channel scope — RESOLVED (2026-07-18, measured during PR-A):** the sandbox blocks standalone exec. On the real MAS 1.3.3 b11 bundle, direct terminal exec of the helper dies at launch with SIGTRAP (exit 133, no output) — its `com.apple.security.app-sandbox` + `com.apple.security.inherit` entitlements require a sandboxed parent process, and a terminal is not one. Scope-out per the baked recommendation: App Store users route to the npm channel (`npx clauge`); the wrapper keeps the Helper.app probes as belt-and-braces (verified they resolve the MAS layout correctly via a stubbed helper). See AGENTS.md landmine #45.
7. **Repo home (new, rev 4) — RESOLVED (owner confirmed 2026-07-18):** build the widget **inside the clauge repo**, not a separate one. Grounds: `clauge status` is a verb on the *existing* CLI dispatcher (`lib/cli/index.js`) inside the *existing* SEA sidecar binary — a separate repo would have to ship a second binary, duplicate the port-discovery/HTTP/test plumbing, drift against the `/v1/usage` contract, and maintain its own CI/release train, for zero isolation benefit. The npm channel (`clauge` package → `server.js`) already ships from this repo and gives Windows the same verbs free. A separate repo becomes worth it only if the widget someday needs a different runtime (e.g. a native Swift/Go binary) or a faster release cadence than the app.
