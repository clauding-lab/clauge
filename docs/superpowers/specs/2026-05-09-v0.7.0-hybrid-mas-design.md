## Problem

Clauge v0.5.0 → v0.6.0 ships data acquisition via three paths today:
- **Local JSONL parsing** of `~/.claude/projects/**/*.jsonl` (Claude Code CLI usage; the killer feature)
- **Clauge Sync browser extension** (claude.ai plan rings, prepaid balance — rides the user's existing browser session)
- **Bookmarklet fallback** (manual one-shot sync via the user's bookmarks bar)

Two structural limitations follow from these paths:

1. **Mac App Store distribution is blocked** at the architectural level. The macOS App Sandbox forbids reading `~/.claude/projects/` (data written by another app — Claude Code CLI), and the Tauri auto-updater is incompatible with App Store policy. Clauge can only ship via direct DMG download, which means SmartScreen-equivalent friction on first install (Gatekeeper warnings) and no listing in the place macOS users naturally search for menu-bar apps.

2. **The browser extension is the only path to claude.ai plan data**, requiring users to install a Chrome extension AND keep claude.ai signed in in the same browser profile. The v0.5.1 auto-detect helps surface the install CTA, but doesn't reduce the underlying friction.

Recent research (HN comment on a Show HN thread for `Usage for Claude` MAS app + open-source clones) revealed two viable architectures used by competing MAS-published Claude usage trackers:

- **Architecture B**: read the OAuth access token Claude Code CLI already stores in macOS Keychain under service name `Claude Code-credentials`, call `api.anthropic.com/api/oauth/usage` directly. Sandbox-friendly. Zero login UI. Works for users with Claude Code CLI installed (Clauge's primary audience).
- **Architecture A**: embed a WKWebView, user signs into claude.ai inside the app, capture session cookies, call `claude.ai/api/organizations/{uuid}/usage`. Established pattern (Hayek's `Usage for Claude` runs this in MAS today). Works for all users including claude.ai-only ones.

Combining these as a hybrid — B primary, A fallback — unlocks both MAS distribution and a zero-config UX for the typical Claude Code user, while leaving the existing extension as a stable third option for browser-only and Windows users.

## Decision

Build a hybrid macOS auth/data architecture and a parallel sandboxed MAS-flavor of Clauge. The DMG flavor keeps everything from v0.6.x (extension supported, Tauri auto-updater enabled). The MAS flavor adds a security-scoped-bookmark flow for JSONL access and removes the auto-updater (Apple owns updates inside the Store).

The browser extension is **kept**, not deprecated. It serves Windows users, `npx clauge` browser-only users, and macOS users who prefer it.

## Scope

**Adds (Rust / Tauri):**
- `src-tauri/src/keychain.rs` (new): macOS Keychain Services wrapper to read the `Claude Code-credentials` entry; extract OAuth access + refresh tokens; return a structured `KeychainCredential` enum.
- `src-tauri/src/anthropic_oauth.rs` (new): bearer-token-authenticated HTTP client for `api.anthropic.com` endpoints; primary call is `GET /api/oauth/usage`; refresh-token flow if access token expired; falls through with `Result::Err` on auth failure.
- `src-tauri/src/claude_ai_session.rs` (new): WKWebView-based login modal (Tauri WebviewWindow); cookie capture; session-cookie persistence in Keychain Services under `com.clauding.clauge.claude-ai-session`; bearer-cookie-authenticated calls to `claude.ai/api/organizations/{uuid}/usage`.
- `src-tauri/src/security_scoped_bookmark.rs` (new, MAS flavor only): wraps macOS NSURL security-scoped bookmark APIs; persists serialized bookmark blob in Tauri store under `claude_projects_bookmark`; `start_accessing_security_scoped_resource()` / `stop_accessing_…` lifecycle.
- `src-tauri/src/connections.rs` (new): unified state machine over the three auth surfaces (Claude Code keychain / claude.ai webview session / browser extension heartbeat); exposes status to dashboard via existing IPC pattern.

**Adds (frontend):**
- `public/connections.js` (new) + Settings → Connections panel (rebrand of existing claude.ai sync card): three independent rows (Claude Code CLI, claude.ai web, Browser extension) + a fourth on MAS flavor (Claude Code logs / security-scoped bookmark).
- First-launch flow on MAS: top-of-dashboard banner asking the user to grant `~/.claude/projects/` access via NSOpenPanel; persists choice; replays each launch.

**Adds (build / distribution):**
- `src-tauri/tauri.mas.conf.json` (new): MAS-overlay tauri config; bundle.targets `["app"]`; references `entitlements.mas.plist`; removes `tauri-plugin-updater` from plugin block; adds `bundle.macOS.entitlements`.
- `src-tauri/entitlements.mas.plist` (new): sandbox + cross-app keychain access groups + user-selected file read + bookmarks app-scope + V8 JIT + network client/server + ad-hoc network.
- `src-tauri/entitlements.dmg.plist` (new — current behavior, but now explicit): non-sandboxed entitlements for the existing direct-download flavor.
- `Cargo.toml`: `mas` feature flag (cfg-gates the security-scoped-bookmark module + "Check for Updates" → Store-redirect behavior).
- New CI matrix entry for MAS-flavor build (third row alongside DMG-macOS and NSIS-Windows).
- `docs/RELEASE_CHECKLIST.md` updates for MAS submission flow.

**Modifies:**
- `src-tauri/src/lib.rs`: setup branch reads connection state from `connections.rs` and routes accordingly. The plain JSONL filesystem read is gated `#[cfg(not(feature = "mas"))]`; MAS flavor uses `security_scoped_bookmark::scoped_read`.
- `server.js`: existing `/api/usage/ingest` POST handler stays; new internal-only IPC route or direct in-process write path for the keychain-piggyback and webview-session paths (they don't go through HTTP — Rust calls Anthropic, writes the result into the same shape the existing usage-store consumes).
- `src-tauri/tauri.conf.json` (DMG flavor base): adds explicit `bundle.macOS.entitlements: "entitlements.dmg.plist"` so the two flavors are symmetrically configured.
- `package.json`: new `build:mas` script wrapping `cargo tauri build --features mas --config ../tauri.mas.conf.json`.

**Unchanged:**
- All existing JSONL parsing (`lib/parser.js`, `lib/aggregator.js`, etc.) — the data model and per-session logic stay; only the file-read mechanism on MAS becomes sandbox-scoped.
- Browser extension (Clauge Sync) — kept at v0.1.8 (or whatever lands in v0.5.1). Not deprecated.
- `npx clauge` browser dashboard path — unaffected; no MAS context applies.
- Windows port from v0.6.0 — completely orthogonal; stays NSIS-only.
- Tauri auto-updater for the DMG flavor — unchanged.

**Out of scope (deliberately):**
- Windows hybrid auth (Windows Credential Manager + WebView2) — defer to v0.8.0 once macOS proves out.
- Microsoft Store submission — defer; MSIX bundle work is a separate cycle.
- Linux — out of scope as before.
- Browser-extension deprecation or feature parity reduction — extension stays at current capability; v0.5.1 auto-detect logic is unaffected.
- Refresh-token flow for cases where Claude Code's keychain entry doesn't include a refresh token — fall through to Architecture A modal.
- Empirical verification of `api.anthropic.com/api/oauth/usage` response shape — done during Phase 1 of implementation, not in spec.

## Architecture

### Two-flavor build

| Flavor | Distribution | Sandbox | Auto-updater | Tauri config |
|---|---|---|---|---|
| **DMG** | GitHub Releases (existing minisign-signed) | No (full FS access) | Yes (existing flow) | `tauri.conf.json` |
| **MAS** | Mac App Store | Yes (App Sandbox) | No (Apple owns updates) | `tauri.mas.conf.json` (overlay) |

A `mas` Cargo feature flag (`#[cfg(feature = "mas")]`) gates the MAS-only code paths (security-scoped bookmark module, "Check for Updates" → Store redirect). The DMG flavor compiles with default features.

### Decision tree at app launch

```
Clauge launches
  │
  ▼
connections.rs::detect()
  ↓
1. Probe macOS Keychain for "Claude Code-credentials"
   ├─ Found, token valid → mode=KEYCHAIN_CC, skip webview
   ├─ Found, token expired → attempt refresh
   │    ├─ refresh succeeds → mode=KEYCHAIN_CC
   │    └─ refresh fails → mode=NEEDS_LOGIN, fall through to step 2
   └─ Not found → mode=NEEDS_LOGIN, fall through to step 2
  ↓
2. Probe Tauri store for stored claude.ai session cookie
   ├─ Found → mode=CLAUDE_AI_SESSION, use cookie
   └─ Not found → mode=NEEDS_LOGIN
  ↓
3. Probe extension heartbeat
   ├─ Recent → mode=EXTENSION (existing v0.5.1 path)
   └─ Stale/absent → keep mode from step 2
  ↓
Dashboard renders Settings → Connections panel reflecting all three states.
On NEEDS_LOGIN, banner offers "Sign in to claude.ai" CTA → Architecture A modal.
```

Multiple modes can coexist (e.g., user has Claude Code installed AND extension running). The `connections.rs` module composes them; the freshest data source wins for any given metric.

### Architecture B — Keychain piggyback (primary)

**File:** `src-tauri/src/keychain.rs`

**Dependency:** `security-framework = "2"` (Rust wrapper around macOS Security.framework). Already cross-platform-safe — gated by `[target.'cfg(target_os = "macos")'.dependencies]`.

**Read flow:**
```rust
use security_framework::passwords::get_generic_password;

pub fn read_claude_code_credentials() -> Result<ClaudeCodeCreds, KeychainError> {
    // service = "Claude Code-credentials", account = anything (we read by service)
    let blob = get_generic_password("Claude Code-credentials", "")?;
    serde_json::from_slice(&blob).map_err(KeychainError::Parse)
}

#[derive(Deserialize)]
pub struct ClaudeCodeCreds {
    pub access_token: String,
    pub refresh_token: Option<String>,
    pub expires_at: Option<String>, // ISO 8601
    // ... other fields ignored
}
```

First read of the entry triggers the standard macOS Keychain access prompt: *"Clauge wants to use your confidential information stored in 'Claude Code-credentials' in your keychain."* User clicks **Always Allow** to make subsequent reads silent.

**API call:** `anthropic_oauth.rs`:
```rust
pub async fn fetch_oauth_usage(token: &str) -> Result<PlanUsage, OAuthError> {
    let client = reqwest::Client::new();
    let res = client
        .get("https://api.anthropic.com/api/oauth/usage")
        .bearer_auth(token)
        .header("anthropic-version", "2023-06-01")
        .send().await?;
    if res.status() == 401 {
        return Err(OAuthError::TokenExpired);
    }
    res.json().await.map_err(Into::into)
}
```

**Empirical verification gap:** the exact response shape of `/api/oauth/usage` is the OSS-community-documented endpoint (HN thread, hamed-elfayome's tracker). Phase 1 of the implementation plan will start with a one-shot fetch + inspect to verify the response includes Session/All-models/Sonnet/Opus utilization fields equivalent to what `claude.ai/api/.../usage` returns today. If the response is materially different from what Clauge's UI expects, the data-mapping layer in `aggregator.js` adapts.

**MAS sandbox entitlement:**
```xml
<key>keychain-access-groups</key>
<array>
  <string>$(AppIdentifierPrefix)com.clauding.clauge</string>
  <string>$(AppIdentifierPrefix)com.anthropic.ClaudeCode</string>
</array>
```

The second array entry requests *cross-app keychain sharing* — letting Clauge read items written by Claude Code's app team. **Apple's MAS reviewer must approve this.** Risk: Apple may deny on the basis that "your app shouldn't read another team's keychain." Mitigation: documented use case in the App Store reviewer notes (Clauge analyzes the user's own Claude usage data; the keychain access is the sandbox-clean alternative to scraping or asking the user to log in twice).

**Failure mode if Apple denies:** the `read_claude_code_credentials()` call returns `KeychainError::AccessDenied`; Clauge in MAS falls through to Architecture A. DMG flavor (non-sandboxed) is unaffected.

### Architecture A — In-app WKWebView login (fallback)

**File:** `src-tauri/src/claude_ai_session.rs`

**Trigger:** `connections.rs::detect()` returns `NEEDS_LOGIN` AND user clicks "Sign in to claude.ai" in the dashboard banner OR Settings → Connections panel.

**Flow:**
1. Open a new Tauri `WebviewWindow` named `auth-claude-ai`, modal-style:
   - URL: `https://claude.ai/login`
   - Size: 520×720
   - Decorations: false (custom title bar matching dashboard style)
   - Skip taskbar: true
2. User signs in normally (Google / email / passkey)
3. The webview navigates to claude.ai's homepage post-login. We detect this via `webview.on_navigation` — if URL host is `claude.ai` and path is `/` or `/chats`, login succeeded.
4. Tauri's `WebviewWindow::cookies(url)` API extracts cookies for `claude.ai` origin. We pull `sessionKey` (Anthropic's claude.ai session cookie name).
5. Persist cookie to Keychain Services under `service = "com.clauding.clauge.claude-ai-session"`, `account = user_email_or_claude_user_id`.
6. Close the auth window; trigger `connections.rs::detect()` to refresh; dashboard re-renders.

**Cookie-authenticated API calls:** subsequent calls to `claude.ai/api/organizations/{uuid}/usage` from Rust set `Cookie: sessionKey=<value>` header; also set `Origin: https://claude.ai` and `Referer: https://claude.ai/` to look browser-shaped.

**Cookie expiry / Cloudflare challenge handling:**
- `claude.ai` sessions typically last 30+ days. On 401/403 from the API, mark session expired; surface "Re-authenticate" CTA in Settings.
- If a 200 response body is HTML containing `cf-chl-bypass` or similar Cloudflare-challenge markers, re-open the auth window — navigating in WKWebView solves the challenge in-context, refreshes the cookie. This is the same dance Hayek's `Usage for Claude` MAS app handles in production.

**MAS sandbox entitlement:**
```xml
<key>com.apple.security.network.client</key>
<true/>
```
Standard outbound HTTPS, no special review.

### Security-scoped bookmark for JSONL access (MAS flavor only)

**File:** `src-tauri/src/security_scoped_bookmark.rs` (cfg-gated to `feature = "mas"`)

**First-launch flow:**
1. After dashboard's first render in MAS flavor, banner appears at top:
   ```
   ⓘ Grant access to your Claude Code logs
   Clauge needs read-only access to ~/.claude/projects/ to show
   per-session analytics. One-click setup.
   [Grant Access]                                  [Skip]
   ```
2. **Grant Access** click → Tauri shell opens NSOpenPanel via macOS native API (or via Tauri's dialog plugin if it supports security-scoped variants):
   - Title: "Choose your Claude Code logs folder"
   - Initial directory: `~/.claude/projects/`
   - Buttons: "Choose" (single-folder selection)
3. User clicks "Choose" — macOS records user-initiated selection. App receives an `NSURL` representing the folder.
4. Convert `NSURL` to security-scoped bookmark blob via `NSURL.bookmarkDataWithOptions(.withSecurityScope)`.
5. Persist serialized bookmark to Tauri store as `claude_projects_bookmark` (binary blob, ~1-2 KB).

**Per-launch use:**
1. Read bookmark blob from Tauri store.
2. `NSURL.URLByResolvingBookmarkData(bookmarkData, options: .withSecurityScope)` → `NSURL`.
3. `url.startAccessingSecurityScopedResource()` returns `bool` — `false` means bookmark is stale (folder moved/deleted, or sandbox context rotated).
   - If false: clear stored bookmark; re-show the banner; user re-grants.
4. Read JSONL files via `lib/session-store.js` (exact same logic as DMG flavor; the URL scoping is transparent).
5. `url.stopAccessingSecurityScopedResource()` after read completes.

**Skip flow:** If user clicks Skip in the banner, JSONL reads are no-ops; dashboard shows plan rings only. Banner persists in Settings → Connections so user can grant later.

**MAS sandbox entitlements:**
```xml
<key>com.apple.security.app-sandbox</key>
<true/>
<key>com.apple.security.files.user-selected.read-only</key>
<true/>
<key>com.apple.security.files.bookmarks.app-scope</key>
<true/>
```

### Settings → Connections UI

Renames the existing "claude.ai sync" Settings panel to **"Connections"**. Four rows (the fourth is MAS-flavor-only):

```
┌─ Connections ──────────────────────────────────────────────┐
│                                                            │
│  Claude Code CLI    🟢 Authenticated                       │
│  via macOS Keychain (Claude Code-credentials)              │
│  [Reconnect]  [About this connection →]                   │
│                                                            │
│  claude.ai web      ⚪ Not signed in                       │
│  Sign in to see plan-ring data even without Claude Code    │
│  [Sign in to claude.ai]                                    │
│                                                            │
│  Browser extension  ⚪ Not detected                        │
│  Optional. Useful for browser-only setups.                 │
│  [Install Clauge Sync →]                                  │
│                                                            │
│  Claude Code logs   🟢 Granted (~/.claude/projects/)      │  ← MAS-flavor only
│  Read-only access for per-session analytics                │
│  [Re-select folder]                                        │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

Each connection is independent. No "primary auth" gating — the dashboard composes data from whichever sources are active. The freshest data wins per-metric (plan rings: keychain B beats webview A beats extension; per-session analytics: JSONL only).

The v0.5.1 install banner becomes connection-aware: only shows for users who have *no* claude.ai data path active (no keychain B, no webview A, no extension). One of the three becoming positive auto-hides the banner.

**File layout:**


```yaml
    - { runner: macos-14,     target: universal-apple-darwin, bundles: 'app,dmg', config: 'tauri.conf.json',     features: '' }       # DMG
```

The MAS flavor build outputs a sandboxed `.app`. Submission to App Store Connect uses Transporter (or `xcrun altool --upload-app`); this is a manual step (Apple credentials + ASC API key required), documented in `RELEASE_CHECKLIST.md`.

### MAS submission specifics

Apple Developer Program: $99/yr (already needed for any code signing; cost wasn't introduced by v0.7.0). App Store Connect listing: needs screenshots (1280×800, 1440×900, 2560×1600 for Mac), app description, support URL, privacy policy URL, App Privacy nutrition label.

App Privacy declarations (Clauge collects):
- **Data Not Linked to You**: Anonymous usage analytics — None (Clauge has no telemetry by design)
- **Data Linked to You**: None
- Privacy policy at https://clauding-lab.github.io/clauge/privacy or similar

App Review Information section needs reviewer notes explaining:
- Why we request `keychain-access-groups` for `com.anthropic.ClaudeCode`: "Clauge analyzes the user's own Claude Code usage. The keychain entry contains an OAuth token Claude Code already wrote; we read it to call Anthropic's official `api.anthropic.com/api/oauth/usage` endpoint. The user explicitly grants this access via the macOS Keychain prompt at first read."
- Why we use security-scoped bookmark for `~/.claude/projects/`: "Same reason — analyzing the user's own logs. The user picks the folder via NSOpenPanel; we never access it without explicit consent."

Review timeline: typical 24-72h, longer for first submission. If the cross-app keychain entitlement is denied, the MAS flavor still ships; users without Claude Code (or who deny the keychain prompt) fall through to Architecture A.

## Decisions made

| # | Decision | Reason |
|---|---|---|
| 1 | Hybrid (B primary, A fallback), not A-only | B is zero-config UX for typical Clauge user (Claude Code installed). A handles claude.ai-only users. Both ship together. |
| 2 | Two-flavor build (DMG + MAS), maintained in parallel | DMG keeps Tauri auto-updater (better UX for direct distribution). MAS gets store discovery + free updates via Apple. Both produced from one tag, both distributed. |
| 3 | Browser extension is KEPT, not deprecated | Serves Windows users + browser-only users + power users who prefer it. Extension code is small + stable; ongoing maintenance cost is low. v0.5.1 auto-detect work is preserved. |
| 4 | `Settings → Connections` panel; each connection independent | Users can have any combination of (keychain CC / webview claude.ai / browser extension). No "primary auth" gating UX — composability over magic. |
| 5 | Security-scoped bookmark for JSONL in MAS flavor | The only sandbox-clean way to read another app's data folder. User-initiated; reviewable; revocable. Skip flow leaves users with plan rings only — graceful. |
| 6 | Drop Tauri auto-updater for MAS flavor | App Store policy requires the Store to own updates. "Check for Updates" button in MAS flavor opens the MAS listing instead. Established pattern (Hayek's app, others). |
| 7 | Cross-app keychain access entitlement requested in Apple review | Required for B to work in MAS. If Apple denies → graceful degradation to A (B path silently fails on MAS only). DMG flavor unaffected. |
| 8 | Endpoint `api.anthropic.com/api/oauth/usage` accepted on faith from OSS-community evidence | HN comment + hamed-elfayome's tracker confirm the endpoint is in use by published apps. Phase 1 of implementation verifies response shape before locking the data-mapping layer. |
| 9 | Cargo `mas` feature flag, NOT a separate codebase fork | Single source of truth; cfg-gates the MAS-only modules. Cleaner than maintaining two divergent repos. |
| 10 | Windows hybrid + Microsoft Store explicitly deferred | Different keychain APIs (Windows Credential Manager), different webview (WebView2), different store (MSIX). Worth a separate cycle (v0.8.0+) once macOS proves out. |

## Open questions / known unknowns

- **`api.anthropic.com/api/oauth/usage` response shape** — verified during Phase 1 first-fetch, not pre-design. Plan accommodates a data-mapping shim if response differs from claude.ai's.
- **Apple's review verdict on cross-app keychain entitlement** — unknown until submission. Clauge isn't the first app to request similar (`Usage for Claude` is in MAS already), so precedent suggests approval is plausible. If denied, A fallback is fine.
- **Refresh token availability in Claude Code's keychain entry** — depends on Claude Code's auth implementation; if the entry is access-token-only (no refresh), the token's 1-hour lifetime forces an A fallback every hour. Worst case the user re-runs `claude /login` periodically; tolerable.
- **Universal vs Apple-Silicon-only for MAS** — current DMG is universal (lipo-merged). MAS submission can be the same. Verify during Phase 1 that the SEA sidecar's `clauge-server-universal-apple-darwin` works inside the sandboxed app.
- **MSIX / Microsoft Store path on Windows** — out of scope for v0.7.0 but the architecture mostly transfers (Windows Credential Manager replaces Keychain; WebView2 replaces WKWebView; AppContainer replaces App Sandbox). Windows hybrid is the v0.8.0 candidate.
