## Item 1 — Popover Quit button (and ⌘Q)

**Today:** `popover/popover.js::quitApp()` (lines ~762-768) posts `{cmd:'quit'}` to the WKWebView's `clauge` script-message handler. `native_popover.rs::handle_script_message` (match at ~198-241) implements only `open_dashboard` and `resize`; `quit` hits the catch-all and logs `unknown script message cmd=quit`. Both the ✕ Quit button and the popover's ⌘Q shortcut are dead. Dates to the v0.5.0 native-popover migration; `ipc::quit_app` exists but is unreachable from the popover (raw WKWebView, no Tauri IPC) and has zero JS callers.

**Fix:** add a `"quit"` match arm in `handle_script_message` mirroring `menu_quit` (~283-288): `if let Some(app) = APP_HANDLE_REF.get() { app.exit(0); }`. Sidecar teardown + port-file removal already happen downstream in lib.rs's `RunEvent::ExitRequested`. No frontend change; no IPC triple registration (webkit channel, not Tauri IPC).

**Rider:** correct the stale header comment at `popover.js:5-6` that claims quit already works.

**Not touched:** `openSettings`'s dead `cmd:'open_settings'` path (no caller since v0.9.4 — wave-2-or-never); the `quit_app` IPC command and its validator exemption (only relevant if a dashboard Quit control is ever added); everything else in native_popover.rs (landmine #11: transient behavior, transparency stack, size constants are deliberate).

**Verify:** manual macOS smoke — popover ✕ Quit and ⌘Q both exit the app cleanly (sidecar gone, port file removed). No E2E possible (landmine #9: tauri-driver has no macOS support).

## Item 2 — Keychain expiry re-read

**Today:** `src-tauri/src/keychain_cache.rs` caches `ClaudeCodeCreds` in a `Mutex<Option<...>>` forever; `invalidate()` (line ~75) has zero production callers. `connections::detect` (~140-155) checks `expires_at` on the cached blob every 30s poll — once expired, the Connections panel shows "OAuth token expired — re-run `claude /login`" indefinitely, even after Claude Code rotates the token in the Keychain. Recovery today is manual only (↻ button → `refresh_credentials` IPC, or app restart). Note: the *briefed* S1 ("401 reuses dead token") is unreachable — the cached token is never sent over the network; `anthropic_oauth::fetch_oauth_usage` (the only bearer-auth + 401-mapping code) has test-only callers. This fix addresses the live inverse bug.

**Fix:** inside `KeychainCache::get_or_load` — on a cache hit whose creds fail `keychain::is_expired`, drop the entry and re-read the Keychain once (then return whatever the re-read yields; a still-expired re-read result is cached and reported as before, no loop). Fixes every current and future consumer at the single choke point.

**Prompt safety (the cache's reason to exist, keychain_cache.rs:1-8):** the re-read fires only while creds are genuinely expired — the same read the manual ↻ performs today. Post-"Always Allow" reads are silent; worst case on MAS before Always-Allow is a prompt only during a genuinely-expired window, which the manual path already incurs. No unconditional refresh-per-poll.

**Not touched:** the dormant `fetch_oauth_usage`/401→`TokenExpired` contract and its pinned test (`token_expired_variant_is_publicly_matchable`) stay as-is for the future Arch-A caller; Keychain item names (landmines #4/#14); no sidecar involvement (token custody is entirely Rust-side).

**Verify:** TDD red-first via the existing `with_reader` injection — (a) expired-hit triggers exactly one re-read and returns fresh creds; (b) non-expired hit does NOT re-read (prompt-safety pin); (c) expired-hit with still-expired re-read reports expired without looping. UI effect: Connections panel self-heals within one 30s poll of Claude Code rotating the token.

## Item 3 — HTTP timeouts (Rust + Node CLI) + log rider

**Today (recon inventory):** three production Rust loopback calls use bare `reqwest::get` with **no timeout** (reqwest has no default): `ipc.rs:470` `proxy_fetch` (no live JS caller, but registered), `native_popover.rs:669` tray-percent poller (30s single-threaded loop — one hung connection freezes the menu-bar % forever), `icloud_publish.rs:112` snapshot GET (5-min loop — a hang wedges iPhone publishing indefinitely and blocks the loop's shutdown check; sits directly on the iPhone-staleness path from the 2026-06-11 wedge incident). Two call sites already build per-call clients with timeouts (`ipc.rs:572` health 2s; `port_discovery.rs:48` probe 1s). A 10s shared client exists (`anthropic_oauth.rs:13` `OAUTH_CLIENT`) but serves only dormant code. Node sidecar's one internet call (LiteLLM, 8s AbortController) is already the best-guarded call in the codebase; the CLI duplicates a 2s AbortController helper verbatim in `lib/cli/_toggle.js` and `lib/cli/config-get.js`.

**Fix (Rust):** new `src-tauri/src/http_client.rs` exposing `LOCAL_CLIENT: Lazy<reqwest::Client>` with a 5s default timeout (`once_cell` + `reqwest` already in Cargo.toml — **no new dependencies**). Adopt at the three bare call sites; consolidate the two per-call builders onto it with per-request `RequestBuilder::timeout` overrides keeping their existing 2s/1s values. `proxy_fetch` stays method-pinned GET (ipc.rs:468-469 threat-model comment). Do not restructure the sibling-loop topology (landmines #10/#36): timeouts go inside `publish_once` / the poller body.

**Fix (Node CLI):** new `lib/http.js` ESM helper `fetchWithTimeout(url, init, timeoutMs)`; adopt in `lib/cost-calculator.js:49`, `lib/cli/_toggle.js:25`, `lib/cli/config-get.js:31` (collapses three bespoke AbortController copies; existing timeout values preserved: 8s LiteLLM, 2s CLI). Bundled via import — no `sea-config.json` ASSETS entry needed; confirm with `npm run test:sea`.

**Rider (same file as the publish timeout):** promote `icloud_publish.rs:74` publish-failure logging from `log::debug!` to `log::warn!` — today a hard local-write failure is invisible at the default log filter while success logs "published".

**Verify:** unit tests where extractable (client config, helper behavior, per-request overrides); `cargo test` + `npm test` + full `npm run check`. Manual hang-check optional (dev `node server.js` needs `CLAUGE_ALLOW_EXTERNAL=1`, landmine #31).

## Success criteria

- Popover ✕ Quit and ⌘Q exit the app (sidecar terminated, port file removed) on both DMG and MAS builds.
- With an expired cached token and a rotated Keychain token, the Connections panel shows authenticated within one 30s poll — no ↻ click, no restart.
- No production HTTP call in src-tauri or lib/cli lacks a timeout (greppable: no bare `reqwest::get` outside tests; no `fetch(` without signal in lib/cli + cost-calculator).
- A simulated hung sidecar response no longer freezes the tray % or the iCloud publish loop past the timeout.
- `npm run check` green on every PR; 4-file version lockstep intact; MAS build 8 uploads clean.
