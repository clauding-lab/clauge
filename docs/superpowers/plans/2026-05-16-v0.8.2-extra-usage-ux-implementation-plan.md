# v0.8.2 EXTRA USAGE UX — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Clauge v0.8.2 — when claude.ai's `/usage` API returns `extra_usage.is_enabled: false` with a `disabled_reason`, the dashboard's EXTRA USAGE card shows "Temporarily gated by Anthropic" instead of the misleading "not configured" text.

**Architecture:** Two-file frontend change + tests + version bump. Parser at `lib/usage-store.js` passes `disabled_reason` through as `disabledReason` (camelCase). Renderer at `public/app.js::renderFinanceSide` adds a third state for "gated" alongside the existing enabled/never-configured states. Forward-compatible reason→text mapping with generic fallback for unknown enum values.

**Tech Stack:** Vanilla JS frontend, Node.js sidecar with Hono, Tauri 2.x shell. Same as v0.8.1.

**Reference spec:** `docs/superpowers/specs/2026-05-16-v0.8.2-extra-usage-ux-design.md`

Replace the existing if/else (lines 297-314 — the section ABOVE the `// claude.ai balance side card` comment) with the three-state version:

```javascript
function renderFinanceSide() {
  const usage = state.data.usage;
  const plan = usage?.plan ?? {};
  const extra = plan.extraUsage;
  const usedEl = document.getElementById('extra-used');
  const capEl = document.getElementById('extra-cap');
  const barEl = document.getElementById('extra-bar');
  const pctEl = document.getElementById('extra-pct');
  const currEl = document.getElementById('extra-currency');

  if (extra && extra.enabled) {
    const used = extra.usedDollars ?? 0;
    const limit = extra.limitDollars ?? 0;
    usedEl.textContent = used.toFixed(2);
    capEl.textContent = limit > 0 ? `/ $${limit.toFixed(2)}` : '';
    let pct = extra.pct;
    if ((pct == null || !Number.isFinite(pct)) && limit > 0) pct = (used / limit) * 100;
    pct = Math.max(0, Math.min(100, pct ?? 0));
    barEl.style.width = `${pct.toFixed(1)}%`;
    pctEl.textContent = `${pct.toFixed(1)}% of cap`;
    currEl.textContent = extra.currency || 'USD';
    barEl.classList.remove('bar-fill--gated');
  } else if (extra && !extra.enabled && extra.disabledReason) {
    // v0.8.2: gated state — Anthropic disabled the feature at the org level.
    // Show the reason instead of misleading "not configured" copy.
    usedEl.textContent = '—';
    capEl.textContent = '';
    barEl.style.width = '100%';
    barEl.classList.add('bar-fill--gated');
    pctEl.textContent = disabledReasonText(extra.disabledReason);
    currEl.textContent = extra.currency || 'USD';
  } else {
    usedEl.textContent = '0.00';
    capEl.textContent = '';
    barEl.style.width = '0%';
    barEl.classList.remove('bar-fill--gated');
    pctEl.textContent = 'not configured';
    currEl.textContent = 'USD';
  }
  // ...claude.ai balance side card (unchanged)...
```

Three behavior notes:
1. Enabled branch also calls `classList.remove('bar-fill--gated')` to reset state when transitioning back from gated → enabled (if Anthropic ungates mid-session).
2. Gated branch sets `barEl.style.width = '100%'` — paired with the gray gated color, this visually communicates "this slot is filled but inactive" rather than "0% used."
3. Never-configured branch also calls `classList.remove('bar-fill--gated')` for symmetric state reset.
