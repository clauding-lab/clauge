# Clauge v1.0.0 — Onboarding Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a ToS-clean, 1–2-click onboarding for Clauge v1.0.0 by (a) removing the `Claude Code-credentials` Keychain reading entirely, (b) replacing it with an optional user-pasted `sk-ant-api03-*` API key in Settings, (c) hoisting claude.ai sign-in into the wizard, (d) adding Apple Developer ID code-signing + notarization to `release.yml`, and (e) demoting the Chrome extension to a Settings tile.

**Architecture:** Three coordinated changes. (1) CI workflow adds Apple Developer ID Application code-signing + notarization on every DMG release using existing membership (Team ID `CY4FK9S7X9`). (2) Rust backend stops reading `Claude Code-credentials` Keychain entry; instead reads a user-pasted `sk-ant-api03-*` API key from its OWN Keychain entry and calls Anthropic's official `/v1/organizations/usage_report/messages` Usage API. (3) Frontend onboarding wizard compresses to 3 steps (Welcome → claude.ai sign-in → optional CLI install), with the Settings panel hosting all post-onboarding configuration including the new API key paste + extension tile.

**Tech Stack:** Tauri 2.x (Rust + WebView2/WebKit), vanilla JS classic-script popover/onboarding code, Hono local server, Apple Developer ID + notarytool in GitHub Actions, `security_framework` Rust crate for macOS Keychain ops, `reqwest` for Anthropic API calls.

**Predecessor design:** `docs/superpowers/specs/2026-05-26-v1.0.0-onboarding-redesign-design.md`. Read it once before starting if you lack context for any task here.

      - name: Import Apple Developer Certificate (macOS only)
        if: matrix.platform == 'macos-latest' || contains(matrix.platform, 'macos')
        env:
          APPLE_CERTIFICATE: ${{ secrets.APPLE_CERTIFICATE }}

          security create-keychain -p "$KEYCHAIN_PASSWORD" build.keychain
          security default-keychain -s build.keychain
          security unlock-keychain -p "$KEYCHAIN_PASSWORD" build.keychain
          security set-keychain-settings -t 3600 -u build.keychain
          security import certificate.p12 -k build.keychain \
            -P "$APPLE_CERTIFICATE_PASSWORD" -T /usr/bin/codesign
          security set-key-partition-list -S apple-tool:,apple:,codesign: \
            -s -k "$KEYCHAIN_PASSWORD" build.keychain
          rm certificate.p12
          # Verify the Developer ID Application identity is now importable
          security find-identity -v -p codesigning build.keychain | grep "Developer ID Application" || {
            echo "::error::Developer ID Application identity not found in keychain after import"
            exit 1

```rust
fn detect_claude_code_state(keychain_cache: &KeychainCache) -> ClaudeCodeState {
    // v1.0.0: no longer reads Claude Code-credentials Keychain entry.
    // Instead, infers state from the local transcript folder.
    let home = match home_dir() {
        Some(h) => h,
        None => return ClaudeCodeState::Unknown,
    };
    let projects = home.join(".claude").join("projects");
    if !projects.exists() {
        return ClaudeCodeState::NotInstalled;
    }
    // Scan for at least one .jsonl file (recursively, one level deep is enough)
    let has_transcripts = std::fs::read_dir(&projects)
        .ok()
        .map(|entries| {
            entries
                .filter_map(Result::ok)
                .any(|e| {
                    e.file_type().map(|t| t.is_dir()).unwrap_or(false)
                        && e.path().read_dir().ok().map(|inner| {
                            inner.filter_map(Result::ok).any(|f| {
                                f.path().extension().and_then(|s| s.to_str()) == Some("jsonl")
                            })
                        }).unwrap_or(false)
                })
        })
        .unwrap_or(false);
    if has_transcripts {
        ClaudeCodeState::Authenticated  // rename to TranscriptsAvailable later
    } else {
        ClaudeCodeState::NotInstalled
    }
}
```

//! API-key-authenticated client for the Anthropic Usage and Cost API.

const ANTHROPIC_API_BASE: &str = "https://api.anthropic.com";
const USAGE_REPORT_PATH: &str = "/v1/organizations/usage_report/messages";

#[derive(Debug, thiserror::Error)]
pub enum AnthropicAdminError {
    #[error("HTTP error: {0}")]
    Http(#[from] reqwest::Error),
    #[error("API key is invalid format (must start with sk-ant-api03-)")]
    InvalidKeyFormat,
    #[error("API returned {status}: {body}")]
    ApiError { status: u16, body: String },
}

pub fn validate_key_format(key: &str) -> Result<(), AnthropicAdminError> {
    if key.starts_with("sk-ant-api03-") && key.len() > 20 {
        Ok(())
    } else {
        Err(AnthropicAdminError::InvalidKeyFormat)
    }
}

/// with `limit=1`). Returns Ok if the key is valid and the call succeeds; Err

pub async fn test_api_key(key: &str) -> Result<(), AnthropicAdminError> {
    validate_key_format(key)?;
    let client = reqwest::Client::builder()
        .timeout(std::time::Duration::from_secs(10))
        .build()?;
    // Use yesterday as the date filter to ensure we have a fast empty response
    // even on new API accounts.
    let yesterday = chrono::Utc::now()
        .checked_sub_signed(chrono::Duration::days(1))
        .ok_or(AnthropicAdminError::ApiError {
            status: 0,
            body: "could not compute yesterday".to_string(),
        })?
        .format("%Y-%m-%dT00:00:00Z")
        .to_string();
    let url = format!(
        "{}{}?starting_at={}&limit=1",
        ANTHROPIC_API_BASE, USAGE_REPORT_PATH, yesterday
    );
    let res = client
        .get(&url)
        .header("x-api-key", key)
        .header("anthropic-version", "2023-06-01")
        .send()
        .await?;
    let status = res.status().as_u16();
    if status == 200 {
        Ok(())
    } else {
        let body = res.text().await.unwrap_or_default();
        Err(AnthropicAdminError::ApiError { status, body })
    }
}

    key: &str,

    else if (t.matches('[data-install-cli]')) installCli();
    else if (t.matches('[data-finish]')) finishWizard();
  });

    if (e.key === 'Enter' && currentStep < TOTAL_STEPS) {
      showStep(currentStep + 1);
    }
  });

## 4. Notarization failure debugging

### Common causes (ranked)

1. **API key expired or revoked** — symptom: `xcrun notarytool` returns 401.
   Fix: rotate per Section 2 above.
2. **2FA state issue on Apple ID account** — symptom: app-specific password
   stops working. (If using API-key path, this doesn't apply.)
3. **Hardened-runtime entitlement mismatch** — symptom: notarization rejects
   the bundle with "the executable does not have the hardened runtime
   enabled." Fix: confirm Tauri's auto-applied hardened-runtime entitlement
   is intact in `src-tauri/entitlements.plist`. If missing, regenerate by
   running `tauri build --bundles dmg` locally and observing the entitlements
   applied.
4. **Bundle ID mismatch** — symptom: notarization succeeds but Gatekeeper
   rejects. Fix: confirm `src-tauri/tauri.conf.json` `identifier` is
   `com.clauding.clauge` and matches your provisioning profile.
5. **Apple service outage** — symptom: notarization times out > 30 min.
   Check https://developer.apple.com/system-status/. Re-run later.

### Debug procedure

1. From the failed CI run, download the `submission.json` artifact if Tauri
   uploaded one (it tries to). Otherwise check the run log for the
   `xcrun notarytool submit` output.
2. Get the submission UUID. Then:
   ```bash
   xcrun notarytool log <submission-uuid> \
     --key AuthKey_<KEY_ID>.p8 \
     --key-id <KEY_ID> \
     --issuer <ISSUER_ID>
   ```
3. The log JSON tells you exactly what Apple rejected.
