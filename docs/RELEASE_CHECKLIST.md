# Clauge Release Checklist

This document tracks the manual + automated steps before tagging a Clauge V3 release.

Since v0.8.0, V3 ships on **both macOS and Windows** from the same Tauri codebase. The pre-tag smoke is therefore split: every release needs to pass **both** the macOS smoke (run on a Mac) **and** the Windows smoke (run on a Windows 10 / 11 machine or VM). The macOS smoke + E2E gaps sections below are unchanged from v0.7.x; the Windows smoke is new for v0.8.0.

## Known issues

- **Tray icon is colored (not monochrome template).** The current `src-tauri/icons/tray-icon.png` and `tray-icon@2x.png` were generated by downscaling the colored 1024×1024 app icon via `sips`. macOS expects menu-bar tray icons to be **template images** — flat black-on-transparent, with the system applying tint based on light/dark menu-bar appearance. Replace with a true monochrome rendering before public release. The source `docs/design/assets/clauge-menubar.svg` exists but uses multiple stroke colors (`#d97757`, `#6a9bcc`, `#faf9f5`) and would need a single-color variant authored before rasterizing.

## Release identifier locations (rotation cheat sheet)

A single source of truth for "where does each release-time identifier or secret live, and how do I rotate it" — adopted from steipete/CodexBar's pattern. The full template lives in `.mac-release.env.example` at the repo root.

| Identifier | Lives in | Rotate via |
|---|---|---|
| `APPLE_TEAM_ID` (`CY4FK9S7X9`) | Apple Developer membership; surfaces in `tauri.mas.conf.json::providerShortName` (on `mas-implement-session` branch) | App Store Connect → Membership |
| `APPLE_ID` (`adnan_du@yahoo.com`) | Apple ID; surfaces in `xcrun notarytool` invocations | Apple ID account settings |
| `APPLE_APP_SPECIFIC_PASSWORD` | GitHub Secret `APPLE_APP_SPECIFIC_PASSWORD` + local `.mac-release.env` | https://appleid.apple.com → App-Specific Passwords |
| `BUNDLE_ID` (`com.clauding.clauge`) | `src-tauri/tauri.conf.json::bundle.identifier`; also load-bearing in keychain item names (see AGENTS.md landmine #4) | DO NOT rotate without coordinated migration of keychain items + ASC record |
| `ASC_APP_ID` (`6770303247`) | App Store Connect app page URL; surfaces in CI/release scripts when MAS work lands | Assigned by Apple on first MAS submission; not user-rotatable |
| `UPDATER_ENDPOINT` (gh-pages `latest.json`) | `src-tauri/tauri.conf.json::plugins.updater.endpoints` | Edit tauri.conf.json + tag a release that re-publishes |
| `TAURI_SIGNING_PRIVATE_KEY` | GitHub Secret + local `.mac-release.env` | `cargo tauri signer generate`, then re-publish all platforms (breaks existing installs' update path) — see plan Task 19 |
| `APPLE_DEV_ACCOUNT_EXPIRES` (`2027-05-17`) | Apple Developer membership renewal date | Renew at App Store Connect → Membership before expiry |

**Local release flow:** copy `.mac-release.env.example` → `.mac-release.env` (gitignored), fill in real values, `source .mac-release.env` before running notarization/signing scripts.

**CI release flow:** GitHub Secrets are authoritative; `.mac-release.env` is for local-machine rotation/manual signing only.

## macOS manual smoke (pre-tag)

```
□ Install fresh DMG on a Mac that doesn't have V3
□ Right-click → Open passes Gatekeeper warning (unsigned ship)
□ Tray icon appears within 2s
□ Click tray → popover opens with real data (rings, sparkline, tabs)
□ Click "Open dashboard →" → V2.2 dashboard renders at 127.0.0.1:<port>
□ Settings → toggle autostart, quit, reboot, app auto-launches
□ Force update check → new version downloads, swaps, restarts
□ Quit app → ps -ef | grep clauge-server returns nothing (no orphan sidecar)
□ Coexistence: launch npm clauge first, then V3 → V3 connects as client
□ Coexistence: quit npm clauge while V3 open → V3 spawns own sidecar within 30s
```

## E2E manual gaps

> **Important — tauri-driver platform support (2026-05-08):** tauri-driver v2.0.6 (the current Tauri-2 compatible release) supports Linux and Windows only. macOS support is upstream TODO (Appium Mac2 Driver integration not yet implemented). The 5-scenario `test/e2e/v3.test.ts` suite is staged but cannot run on macOS today; on a Mac, `npm run test:e2e` exits with "tauri-driver is not supported on this platform". Until upstream lands macOS support (or until we run the suite from a Linux CI runner with cross-compiled Tauri targets), **all release validation on Mac is manual.** The scenarios below cover both the natively-tauri-driver-impossible cases and the platform-blocked automated set.

The following scenarios cannot be automated via tauri-driver and require manual verification before release:

- Left-click on tray icon → popover appears (tauri-driver doesn't trigger tray events; AppleScript fallback unreliable)
- Vibrancy material visible (semi-transparent macOS-native popover effect)
- Cmd+Q exits the app cleanly (no orphan sidecar process: `ps -ef | grep clauge-server`)
- Auto-update download → quarantine strip → relaunch from `/Applications/Clauge.app`
- macOS notification permission first prompt
- Re-launch → window state restored at same size/position as previous quit (spec §8.5 row 6)

The following are *staged in `test/e2e/v3.test.ts`* but blocked by the macOS platform gap above and currently must also be eyeballed manually before tag:

- App launches → tray icon present
- Popover URL is `popover/index.html`
- `open_dashboard` IPC creates a second window
- `set_autostart` toggle flips state
- `quit_app` IPC exits within 3s

## Windows manual smoke (pre-tag)

Run on a Windows 10 or 11 machine / VM with no prior Clauge install.

### Install
- [ ] Download `Clauge_<version>_x64-setup.exe` from the GitHub Release.
- [ ] Browser warns about the download — click "Keep anyway" / "More info → Keep."
- [ ] Run the .exe. SmartScreen "Windows protected your PC" appears.
      Click "More info" → "Run anyway."
- [ ] NSIS installer runs. Verify install location reads
      `%LOCALAPPDATA%\Programs\Clauge` (per-user, no UAC admin prompt).
- [ ] Install completes WITHOUT a UAC/admin elevation prompt.
- [ ] Start Menu has a "Clauge" entry. Pin to taskbar.

### First launch
- [ ] Click Start → Clauge. Dashboard window opens at 1100×800.
- [ ] First-launch wizard appears (560×640 modal, "Welcome to Clauge").
- [ ] Walk through wizard Steps 1-4. The "macOS Keychain" mention in
      the wizard text should still read fine — Windows users skip past it.
- [ ] Click Connect on the final step. Sidecar reads
      `%USERPROFILE%\.claude\.credentials.json`. Dashboard renders rings.
- [ ] Re-open the app. Wizard does NOT reappear (onboarding_completed flag
      persists across launches).

### Settings / runtime
- [ ] Settings → General → Launch at login toggle persists across reboot.
- [ ] Settings → Connections → ↻ Refresh button works.
- [ ] Settings → Updates → Check Now returns "up to date" (or shows a known-
      newer test build).
- [ ] Close the dashboard window. Task Manager shows no lingering
      `clauge-server.exe` or `Clauge.exe` processes after ~5 seconds.
- [ ] Re-launch from Start Menu. Dashboard reopens; sidecar respawns.

### Cold-launch self-heal (orphan-sidecar)
- [ ] Install v<previous-rc>. Launch it once so the sidecar starts.
- [ ] Close the Tauri shell window, but leave `clauge-server.exe` running
      in Task Manager (do NOT use Task Manager → End Task).
- [ ] Install the new v<current-rc> over the top (auto-update path or
      manual .exe).
- [ ] Launch the new version. Within ~3 seconds, the orphan should be killed
      (taskkill /F /PID) and a fresh sidecar should spawn.
- [ ] Settings → About → version reads the new version.

### Auto-update flow (cross-version)
- [ ] Install v0.8.0-rc1. Tag v0.8.0-rc2 with a one-line code change.
- [ ] Wait for CI to publish; confirm gh-pages `latest.json` has both
      `darwin-aarch64`, `darwin-x86_64`, AND `windows-x86_64` entries
      with the rc2 version.
- [ ] In the running v0.8.0-rc1: Settings → Updates → Check Now.
- [ ] Update downloads + installs. Click Restart Now.
- [ ] Confirm Settings → About shows rc2 after the relaunch.

### Known issues to NOT treat as smoke failures
- SmartScreen "publisher unknown" warning is expected (Authenticode deferred).
- Two cosmetic font 404s (`inter-latin-variable.woff2`,
  `jetbrains-mono-latin-variable.woff2`) in DevTools console are pre-existing
  v0.7.x carryover. Cosmetic.
- claude.ai connection row in dashboard shows "Not Connected" without a
  Sign in button on Windows — Architecture A is deferred to v0.8.x.

## Tagging a release

1. Bump version in `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`
2. Update `CHANGELOG.md`
3. Commit: `git commit -am "chore: release vX.Y.Z"`
4. Tag: `git tag vX.Y.Z`
5. Push: `git push origin main --tags`
6. GitHub Actions release workflow publishes DMG + updates `gh-pages/latest.json`
7. Verify the GitHub Releases page has the `.dmg` and `.dmg.sig` artifacts
